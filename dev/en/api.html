Engine API: hooks and g.*

Everything a card script can call and every hook it can have, as the engine registers them. Arguments in italics are optional. Types: entity — an entity id (a number), player — 0 or 1, tag — a mechanic name (the pack's or the engine's), card id — a string from cards.json. How these pieces fit together: Card scripts in Lua.

Generated from rust/engine/src/lua.rs by tools/lua_api.py, with the words of docs/packs/api.md.

Hooks#

The keys of a card's hook set (a table returned from a script file). Read-only hooks run while the engine only looks at the game: their g has the queries only.

HookValueWhen it runs
target"any" | {base = …, filter = fn(g, me, t) → bool}The card (or power) needs a target. Bases: any, minion, enemy_minion, friendly_minion, enemy_char, friendly_char, enemy_hero (alias enemy_champion). Enemy STEALTH is never a target; SPELLPROOF blocks spells and powers. A minion's battlecry target is optional (no valid target: it is played without one); a spell's is required. filter is read-only.

Target kinds#

For target = "…" or target = {base = "…", filter = fn}: any, minion, enemy_minion, friendly_minion, enemy_char, friendly_char, enemy_hero

Events#

on, now and secret hooks get the event as a table: ev.type, and the fields of that type. Entity ids are numbers; "none" is -1 in events (not nil). A field that the event lacks is nil — compare carefully (ev.target >= 0 fails on nil).

Changing an event: assign to the table (ev.countered = true, ev.target = n, ev.amount = 0). When the hook returns, changed fields are copied back into the logged event, which the engine then reads (a countered spell does not run; a redirected spell hits the new target; predamage amounts replace the damage).
