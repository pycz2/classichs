Classic HS: как устроена система

Godot 4.7.2 + Rust · версия 0.28.0 · состояние на 16.10.2026

Нажмите на блок схемы, чтобы прочитать о нём. Переключатель «Обзор / Подробнее / Всё» наверху добавляет файлы, классы и связи, а на уровне «Всё» ещё и пошаговые потоки со ссылками файл:строка.

В двух словах. Игра — это пакет игры (файл .cardpack, zip): правила, карты и их логика на Lua, названия механик, тексты на 8 языках, арт, звуки, музыка, ранги, таймеры, оформление. Встроены два пакета: «Классика 2014» (прежняя игра) и «Неонопад» (киберпанк, 3 чемпиона, 60 карт). Движок правил на Rust (rust/engine) знает только общие механики карточной игры и исполняет скрипты карт своим интерпретатором Lua (rust/script). Он детерминированный, принимает JSON-запрос (загрузить пакет, новая партия, ход, законные ходы, ход бота, снимок стола) и возвращает JSON-ответ. Этот же крейт работает везде: на игровом сервере как обычная зависимость, в настольных и Android-сборках как библиотека GDExtension, в браузере как WebAssembly. Godot — тонкий клиент: PackManager выбирает активный пакет, мост Rules передаёт его правила в движок, отправляет ходы, получает снимки и события, а интерфейс рисует их картами, артом и темой пакета. Игровой слой (Match) решает, кто здесь главный: локальный движок (тренировка с ботом, обучение, отладка, игра по кодам) или сервер. Онлайн работает двумя способами. По кодам без сервера: два браузера соединяются по WebRTC, договариваются о пакете (при нужде пакет передаётся по тому же каналу), у каждого своя копия партии в своём движке, после каждого хода они сверяют хэш (lockstep). Через необязательный игровой сервер на Rust (server/): сервер хранит пакеты в S3 или в папке, сам ведёт партию в пакете этой игры, проверяет каждый ход и присылает каждому игроку только то, что тот может видеть. Там же аккаунты, ранги по каждому пакету, Арена, друзья и чаты. Клиент может быть подключён к нескольким серверам сразу.

  • Движок без контента. В rust/engine/src нет ни одной карты, класса или механики конкретной игры: всё приходит из пакета (rules.json, cards.json, scripts/*.lua, миссии). Встроенный набор правил — пакет Classic, он вшивается при сборке. Перенос всех карт Classic с Rust на Lua проверен на 7833 записанных партиях: те же события и тот же хэш состояния.
  • Детерминизм. Генератор случайных чисел PCG32 как у Godot с seed партии, никаких float ни в движке, ни в Lua (там только целые), явный порядок обхода (pairs идёт в порядке вставки). Одинаковые пакет, seed и ходы всегда дают одинаковую партию, поэтому игре по кодам хватает пересылки ходов.
  • Два хэша пакета. rules_hash — только то, что меняет игру (правила, карты без оформления, миссии, скрипты): по нему сверяются партии, сервер и соперник по кодам. content_hash — весь пакет: по нему кэш, скачивание и передача. Формат: docs/packs/format.md.
  • Одна сцена. ui/main.tscn содержит только корневой Control, все экраны — классы GDScript, которые ui/main.gd подменяет друг другом. Поверх экранов — оверлей друзей и чатов (Social, вкладка на каждый сервер).
  • Данные отдельно от кода. Исходник пакета — папка packs/<имя>/; Classic при сборке ещё берёт карты, раскладки и реплики из data/, арт из art/cards, звук из audio/. Собирает и проверяет пакеты tools/pack.py; готовые packs/*.cardpack в git не хранятся. Переводы интерфейса и журнал изменений по-прежнему в data/.
  • Тесты на четырёх уровнях. Lua — 54 теста rust/script/tests (семантика, лимиты, песочница). Правила — rust/engine/tests: паритет 7833 партий, API, пакеты, карты «Неонопада». Интерфейс и потоки — 389 тестов Godot в 48 файлах tests/test_*.gd. Сервер — 37 тестов: полные партии ботами, проверка, что чужие карты не утекают, пакеты, админка.
  • Сервер необязателен. Игра по кодам работает и без него. Сервер — отдельная программа classichs-server (Rust, tokio, axum, SeaORM, SQLite, object_store) с админкой в браузере; в Docker рядом с ним SeaweedFS как S3. Партию ведёт он сам, поэтому изменённый клиент не может ни сделать незаконный ход, ни подсмотреть руку соперника. На аккаунт одно подключение: новый вход выкидывает старый (kicked).
  • Выпуск. Версия в project.godot, журнал на 8 языках, тег vX.Y.Z, сайт через tools/build_site.sh --publish в ветку gh-pages. GitHub Actions на каждый тег собирает движок под каждую платформу, игру под все платформы и сервер для Linux, Windows и macOS.
