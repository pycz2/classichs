Как сделать стабильную подпись Android

Добавьте в Settings → Secrets репозитория: ANDROID_KEYSTORE_BASE64 (keystore в base64), ANDROID_KEYSTORE_USER, ANDROID_KEYSTORE_PASSWORD. Тогда обновления ставятся поверх.

Как собрать локально
tools/export_all.sh web windows macos linux   # android и AppImage — в CI

Игровой сервер на Rust

эксперимент, вышел в 0.26.0: код, проверка на этом компьютере, сборки в релизах; нигде не размещён
Клиент Godot⇄ WebSocket ws://localhost:7377 ⇄Сервер (Rust, tokio + axum)⇄ TCP 127.0.0.1 ⇄Судья: игра без окна (-- --referee)
SQLite: аккаунты, сессии, друзья, сообщения, ранги, аренаАдминка /admin

Логика игры. Движок правил один — тот, что в игре. Сервер запускает игру без окна как «судью» и передаёт ей каждый ход. Ход идёт сопернику, только если судья его принял и состояние совпало с тем, что прислал клиент. Нечестный ход — поражение.

Безопасность. Пароли — argon2id; сессии — случайные 256-битные токены, в базе только их SHA-256; ограничение частоты входа; проверка каждого сообщения; админка с отдельным входом, cookie HttpOnly + SameSite=Strict, CSRF-токены; SQL только с параметрами.

Режимы. Обычная игра (скрытый MMR), рейтинговая (25 рангов 2014 года, звёзды, серии побед, Легенда, сезоны по месяцам), арена (12 побед или 3 поражения, одна колода), дружеские игры по приглашению. Правила 2014 года — по Hearthstone Wiki: Ranked 2013–2020 и Arena; подробности — в docs/superpowers/specs/2026-10-15-ranked-research.md.

Поиск соперника. Окно поиска растёт с ожиданием: обычная игра — MMR ±50 и +25 в секунду; рейтинговая — ±2 звезды и +1 каждые 5 секунд; арена — разница в счёте забега +1 каждые 10 секунд.

Друзья. Уникальный тег, до 200 друзей, запросы, сообщения, блокировка (запрещает приглашения и сообщения, но не ладдер).

Порт: 7377 (WebSocket и админка на одном порту). Код: server/src/ — 9 файлов, ≈2800 строк Rust; 19 тестов Rust с поддельным судьёй, один из них проверяет и настоящего судью, если задать CLASSICHS_GODOT и CLASSICHS_PROJECT.

Ограничение сейчас: клиенты по-прежнему знают всё состояние партии (руку и колоду соперника можно прочитать изменённым клиентом). Это уйдёт с тонким клиентом после переноса движка на Rust.

Ошибки, которые нашла проверка (исправлены в 0.26.0 и 0.26.1)
  • Ходы соперника терялись: экран партии переносил канал игры к себе, и связь с сервером забывала этот канал. Тест: tests/test_server_view.gd.
  • Лобби после игры не показывало итог: подписка на итог отключалась на первом же сообщении.
  • Вкладка арены во время забега предлагала начать новый забег.
  • В скачиваемой игре (Windows, macOS, Linux, Android) кнопка «Сетевая игра» была выключена: она требовала WebRTC, а он есть только в браузере. Исправлено в 0.26.1: сервер доступен везде, игра по кодам — в браузере.
  • Пустой тег показывался как «<null>»; номер Легенды читался не из того поля; строки друзей обрезались; чат закрывал кнопки.

Единый движок на Rust

предложение (исследование: docs/superpowers/specs/2026-10-15-rust-engine-research.md)
Вывод. Сейчас — сервер на Rust и судья на текущем движке (сделано). Потом — перенос движка в крейт Rust и подключение везде через одну функцию api::call(json) → json.
ФазаЧтоОценка
0Сервер + судья на GDScript (сделано)—
1В клиенте общий интерфейс правил и view(player): интерфейс не лезет во внутренности движка (≈230 мест в 15 файлах)1–2 недели
2Порт в крейт engine: по файлу Rust на каждый cards/*.gd, данные карт остаются в cards.json; проверка паритета на записанных играх (хэш после каждого хода)3–6 недель
3Сервер на нативном движке, судья рядом ещё один выпуск для сверкидни
4Клиенты: gdext для Windows/Linux/macOS/Android; в браузере — отдельный модуль WASM через JavaScriptBridge (gdext в вебе пока экспериментальный: nightly Rust, особые шаблоны)1–2 недели
Что важно для детерминизма
  • ГСЧ — стандартный PCG32, хэш состояния — SHA-256 от JSON с сортированными ключами: переносимо.
  • hash([seed, "mulligan", p]) использует внутренний хэш Godot — заменить на явную функцию и поднять версию протокола.
  • Хуки карт меняют события на месте (Контрзаклинание, Ледяная глыба) — переносить аккуратно.

  • Начинать ли перенос сразу после сервера.
  • Сделать ли сервер основным сетевым режимом, оставив прямую игру для друзей.

Отделение движка от контента Blizzard

план (docs/superpowers/specs/2026-10-15-content-separation-plan.md)

Название игры

Рекомендация: Inglestone (ingle — огонь в очаге) или Emberstone. Заняты: Firestone, Stonehearth, Hearthfire, Fireside. Перед выбором нужна проверка торговых марок.

Как два игрока играют в одни правила

hello: id и хэш правил пакета→у гостя нет пакета?→хозяин предлагает передать правила и тексты (без арта)→гость соглашается→игра

В пакетах нет скриптов: эффекты — маленький JSON-язык (≈25 действий) плюс встроенные эффекты движка. Чужой код не исполняется. Сервер принимает только одобренные хэши пакетов.

Фазы

  1. Слой пакета без изменения поведения.
  2. Переименование механик в движке.
  3. Язык эффектов и перевод классики (самое рискованное).
  4. Вынос названий и текстов (≈430 строк в 8 языках).
  5. Свой нейтральный стартовый пакет (дизайн карт).
  6. Импорт пакетов.
  7. Сеть.
  8. Переименование игры (сохранить папку user:// и id пакета Android, чтобы не потерять колоды).
