# 0.32 and 0.40 "Classic Heroes Showdown" — plan

Agreed with the owner on 2026-11-02. Two releases: **0.32** (part A, fixes on today's menus) and **0.40**
(part B, the new concept, then the data migration). Nothing is released in between.

## Part A — 0.32

| # | What | Notes |
|---|---|---|
| A1 | Android: pasting into the login password field does nothing (keyboard's paste key, long press) | debug on the owner's phone over Wi-Fi adb; a "Paste" button beside the login fields on every platform |
| A2 | Match events in strict order, every effect visible, both ways | the opponent's card flies out of the hand, is shown, an arrow to its target, then its effects; sequential effects one by one (Mad Bomber, Arcane Missiles); battlecries step by step; a faster animation speed changes only the speed |
| A3 | Mulligan animation | replaced cards go to the deck, kept ones stay; new ones come from the deck to the old places; the Coin appears (animated); the cards go to the hand in the same order |
| A4 | While searching for a server game | other queues, Arena start, logout, game change are disabled until the search is cancelled; friends and chat stay |
| A5 | Decks of a logged-in player on the server | server table + API; in the deck list a per-deck "on the server / only here" tick; every client |
| A6 | Web: never an old cached version | `version.json` read past the cache at start; a newer version: the service worker updates, the old cache goes, the page reloads; cache named by version; offline still works |

## Part B — 0.40 "Classic Heroes Showdown" (short: Classic HS)

- **B1 Rename** everywhere (game, site, README, admin, release text). Kept: Android package id
  `io.github.pycz2.classichs`, the repository, the site URL, the user data folder (`custom_user_dir`).
- **B2 Main menu:** Play, Settings, Exit (not on the web). One neutral menu music.
- **B3 Global settings:** language, music and sound volume, card back (a neutral set), animation speed,
  screen shake, fullscreen. Gone from there: music/art sets, servers, the name, Debug tools.
- **B4 Play →** "Without a server" / "Through a server" (EN "Direct" / "Server").
- **B5 Without a server:** the game library (today's "Games": installed packs, info, import, delete, art /
  sound / music sets per game) → a **game menu styled by the pack** (its music, pictures, colours, font):
  Collection, Training (bot), Code play (WebRTC; the name is asked right before it), Tutorial (only when the
  pack has one), Settings (the global ones + **Debug tools**, only inside a game), Leave the game. Decks are
  local per pack (deleting the pack deletes them). The Classic tutorial (missions, intro texts, effects such
  as rain) moves into the pack.
- **B6 Through a server:** connections (empty, many; the same address with different logins is allowed; add,
  delete, log in, register) → server home (friends, chat, name) → the server's games → per game the art and
  music choice is kept on the server → the game menu as in B5, but Play opens ranked / casual / Arena;
  Training and Tutorial too; decks on the server; Collection can **copy local decks** of an installed pack
  with the same rules hash (tick the decks, copy).
- **B7 Engine / pack boundary:** everything of a game is in its pack (menu look, menu music, tutorial, effects,
  deck templates, texts); the client is a neutral shell. `docs/packs/format.md` grows; Neon proves it.
- **B8 Decks:** no ready-made decks in the player's list; a new deck: class → "from scratch" or "from a
  template" (the pack's `decks/`: name, mana curve, description). Training with no decks: asks to create one.
  Decks players saved before stay. The bots keep their own decks (rust/brain; Classic only for now).
- **B9 Docs for game makers on the site** (GitHub Pages, linked from the landing page "For developers"):
  the pack format, how to build one (`tools/pack.py`), Lua card scripting (syntax, how the interpreter runs,
  the `g.*` API), testing; a pack helper in the client (build, validate, test a pack).
- **B10 Landing page** in the Neonfall style, screenshots with Neonfall by default.
- **B11 Neonfall art:** a simple 2D picture set drawn with Codex (a separate agent, stops at the Codex limit).
- **B12 Migration** at the end: settings (sets move into per-game settings), decks (into the pack they belong
  to), the user data folder kept; a test with an old user folder.
- **B13 Architecture docs on the site** (beside B9, linked from the landing page): the whole game, interactive —
  a top-level block diagram (client shell, rules engine, packs, Lua scripts, server, bots, transports), and a
  drill-down into every component (its parts, data flows, step-by-step flows with file links); clear and
  good-looking. Grows out of today's docs/architecture/index.html, updated to 0.40.

## How the work runs

- Agents in their own worktrees, in parallel: B11 (Neonfall art, Codex, stops at the limit), A6 (web cache),
  A5 (server decks). The main session: A1 (on the owner's phone), A4, A2, A3; then part B.
- Every part with tests; the full suites (`./run_tests.sh`, `cd server && cargo test --release`,
  `cd rust && cargo test --release`) green before a release; real checks (phone, browser, a local server).
- Commits stay local until a release: one push for 0.32, one for 0.40 (CI on every push builds all platforms).
