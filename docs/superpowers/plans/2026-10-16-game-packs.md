# Пакеты игр: движок без контента, правила на Lua, несколько серверов, S3, «Неон»

Дата: 2026-10-16. Статус: план к выполнению (владелец просил полный план до начала работ и работу строго по нему).
Основа: `docs/superpowers/specs/2026-10-15-content-separation-plan.md` (переименования, формат пакета), `docs/superpowers/specs/2026-10-15-thin-client-design.md` (движок на Rust, тонкий клиент, авторитетный сервер).

## 0. Цель в одном абзаце

Движок (`rust/engine`) знает только общие механики и ничего не знает о Hearthstone. Всё, что делает игру конкретной игрой — правила, чемпионы, карты, их логика, названия механик, тексты на всех языках, арты (несколько наборов), звуки, музыка, реплики, ранги, таймеры, режимы, — лежит в одном zip-файле `.cardpack`. Логика карт написана на маленьком безопасном подмножестве Lua, которое исполняет сам движок. Нынешняя игра становится пакетом «Classic 2014» и обязана вести себя ровно как сейчас (проверка на 7833 записанных партиях). Новый нейтральный пакет «Неон» (киберпанк, 3 чемпиона, ≤ 60 карт, свой арт, звуки и музыка) стоит на сервере по умолчанию. Пакеты переходят между игроками в P2P и через сервер (S3). Клиент подключается к нескольким серверам сразу. Второй вход в тот же аккаунт выкидывает первый.

## 1. Решения (принимаю сам, по делу; меняются только с записью сюда)

| # | Вопрос | Решение | Почему |
|---|---|---|---|
| D1 | Чем исполнять Lua | Свой интерпретатор подмножества Lua на Rust (крейт `rust/script`) | Нужны детерминизм (одинаковые хэши на всех платформах), сборка в `wasm32-unknown-unknown`, жёсткая песочница и лимит шагов. C-Lua/Luau плохо собираются в wasm без emscripten; чистые Rust-реализации Lua сырые. Подмножество маленькое — свой интерпретатор проще проверить. |
| D2 | Числа в Lua | Только целые (i64) и строки, bool, nil, таблицы, функции. Дробные числа запрещены | Детерминизм и одинаковое поведение во всех сборках. В правилах карт дроби не нужны. |
| D3 | Что запрещено в Lua | `io`, `os`, `require`, `load`, `dofile`, `debug`, `string.dump`, метатаблицы, корутины, `goto`, глобальные присваивания вне модуля карты | Песочница: без файлов, сети, времени, внешнего кода. |
| D4 | Порядок `pairs` | Порядок вставки (детерминированный) | Иначе хэши разойдутся между платформами. |
| D5 | Лимиты | Шаги на один вызов хука (по умолчанию 200 000), глубина вызовов 200, размер таблицы 10 000, длина строки 64 КБ; превышение — ошибка карты, партия заканчивается «что-то не сходится» без бана | Защита от зависаний и бомб. |
| D6 | Имена механик | Внутри движка — нейтральный словарь (GUARD, HASTE, BARRIER, DOUBLE_ATTACK, STEALTH, ON_PLAY, ON_DEATH, WOUNDED, MANA_LOCK, TRAP, CHAMPION, POWER, …, таблица 4.2 плана отделения контента). Пакет задаёт свои имена и тексты для каждого механизма | Движок без чужих терминов, пакеты называют механики по-своему. |
| D7 | Сериализация состояния | Снимок и хэш пишут теги **именами пакета** | Тогда пакет «Classic» даёт ровно те же хэши, что сегодня, и 7833 партии остаются проверкой паритета навсегда. |
| D8 | Хэши пакета | `rules_hash` = SHA-256 от правил, карт, механик и скриптов (то, что влияет на игру); `content_hash` = SHA-256 по содержимому всех файлов (пути + SHA-256 каждого файла; не байты zip, чтобы не зависеть от сжатия) — уточнено в фазе A2, детали в `docs/packs/format.md` | Партии привязаны к `rules_hash`; разный арт не мешает играть вместе. |
| D9 | Где пакеты в клиенте | Встроенные: `res://packs/*.cardpack` (Classic и Неон); скачанные и импортированные: `user://packs/<content_hash>.cardpack` + индекс; чтение через `ZIPReader` без распаковки | Работает и в вебе (user:// = IndexedDB), и в нативе. |
| D10 | Хранилище пакетов на сервере | S3 API (крейт `object_store` или `aws-sdk-s3`/`rust-s3`), два backend: S3 и локальная папка. В `docker-compose.yml` — сервер + S3-совместимое хранилище (выбрать живое и простое: Garage / SeaweedFS / MinIO из последнего доступного образа; записать выбор сюда) | MinIO перестал выпускать бесплатные сборки в 2025; протокол S3 оставляет выбор открытым. | **Выбрано (A3): SeaweedFS** (`chrislusf/seaweedfs:4.48`, `weed mini`, бакет создаётся при старте; образы MinIO больше не скачиваются, Garage требует ручной настройки).
| D11 | Сервер и пакеты | Админ загружает, включает, выключает и удаляет пакеты; «Неон» ставится при первом запуске; сервер проверяет пакет движком (загрузка, компиляция скриптов, пробная партия ботов) | Кривой пакет не должен ронять сервер. |
| D12 | Свои пакеты игроков | Игрок загружает свой пакет на сервер (лимит размера и числа), он виден ему и тем, кого он приглашает; в очередях — только пакеты админа | Ладдер честный, дружеские игры свободные. |
| D13 | Передача в P2P | Хост предлагает пакет, гость соглашается, куски по 32 КБ с подтверждением по существующему каналу, проверка `content_hash`, кэш | Без сервера, с согласия. |
| D14 | Несколько серверов | Список серверов в настройках; у каждого своя сессия, свой токен, свои друзья; оверлей друзей с вкладками серверов | Как просил владелец. |
| D15 | Один вход на аккаунт | Новый вход (login/resume) закрывает прежнее соединение: прежний клиент получает `kicked {reason: "another_login"}`, забывает автоповтор до действия игрока; партия продолжается в новом соединении (rejoin) | Как просил владелец. |
| D16 | Графические эффекты | Каталог именованных эффектов в клиенте (`fx`): например `bolt`, `fireball`, `nova`, `heal_glow`, `shield_up`, `summon_burst`, `buff_glow`, `freeze`, `drain`, `explosion`, … Карты пакета ссылаются на имена; неизвестное имя — эффект по умолчанию | Эффекты переиспользуются, пакеты их не реализуют. |
| D17 | Ранги и режимы | В `rules.json` пакета: ранги (имена, звёзды, эмблемы, «пол», серии побед, легенда), режимы (constructed, arena: число героев, выборы, победы/поражения, веса редкостей), таймеры (ход, фитиль, муллиган, запас), лимиты (здоровье, мана, рука, стол, колода, копии) | Как просил владелец. |
| D18 | Обучение (Classic) | Миссии обучения — часть пакета Classic (данные + скрипты Lua с хуками миссии); в «Неоне» обучения нет | Обучение — контент. |
| D19 | Документация | `docs/packs/` (Markdown): формат пакета, `rules.json`, карты, подмножество Lua, API движка для скриптов, каталог эффектов, как собрать и проверить пакет; плюс `tools/pack.py` для сборки и проверки | Пакеты должны уметь делать люди. |

## 2. Формат `.cardpack` (кратко; полностью — в `docs/packs/format.md`)

```
manifest.json      format, id, version, name/description по языкам, authors, engine (минимальная версия), default_locale, locales,
                   art_sets [{id, name}], sound_sets, music_sets, card_back, logo, builtin_fx (какие эффекты нужны)
rules.json         лимиты, таймеры, мулиган, «монета», усталость, режимы, ранги, классы, расы, редкости,
                   mechanics: { "<имя в пакете>": {"engine": "GUARD", "name": {..}, "tip": {..}} }
cards.json         [{id, type (MINION|SPELL|WEAPON|CHAMPION|POWER|ENCHANTMENT), class, rarity, cost, atk, hp, durability,
                     race, keywords [...], collectible, set, script: "scripts/<file>.lua#<card>", fx: {play, attack, death, spell},
                     sounds: {play, attack, death}, voice}]
scripts/*.lua      логика карт (модуль возвращает таблицу карт с хуками)
locales/<lang>.json  имена и тексты карт, механик, классов, UI-строки пакета
layout/<lang>.json   (необязательно) ручная раскладка текста карт (у Classic она уже есть)
art/<set>/<id>.webp|jpg, sounds/<set>/..., music/<set>/..., voice/<lang>/...
decks/*.json       готовые колоды;  missions/*.json + scripts (обучение, необязательно)
```

Скрипт карты (пример «Огненный столп» / любой «нанести 4 урона всем врагам-существам»):

```lua
return {
  CS2_032 = {
    spell = function(g, me, target)
      for _, m in ipairs(g.minions(g.enemy(me))) do
        g.damage(me, m, g.spell_dmg(me, 4))
      end
    end,
  },
}
```

API для скриптов (`g`) повторяет примитивы движка: `damage, heal, destroy, summon, draw, add_to_hand, buff, set_stats, silence, freeze, transform, return_to_hand, take_control, equip, gain_armor, gain_mana, discard_random, minions, chars, hero, weapon, adjacent, enemy, ctrl, tag/has/set_tag, random/pick/shuffle (через ГСЧ партии), event, request_choice, cost_mod, aura_add, …`, плюс хелперы коллекций (`list.filter/map/count/any/sort_by`). Хуки карты: `battlecry/on_play, spell, combo, deathrattle/on_death, on = {event = fn}, now = {predamage = fn}, aura, aura_final, secret = {event, cond, effect}, cost_mod, cost_aura, can_play, target = {base, filter}, choose_one, on_choose, hero_power`.

## 3. Фазы и порядок

Зависимости: A1, A2, A3, A4 идут параллельно → B (движок с пакетами) → C (клиент) и D (сервер) параллельно → E (Неон, проверка, релиз, отчёт).

### Фаза 0 (сделано сейчас)
- `tools/android_keystore_check.py`: локальная страница проверки секретов подписи Android. Готово, закоммичено.

### Фаза A1 — интерпретатор подмножества Lua (`rust/script`)
- Лексер, парсер (локальные переменные, функции и замыкания, `if/elseif/else`, `while`, числовой и `for … in ipairs/pairs`, `return`, `break`, таблицы, методы `a:b()`, конкатенация, сравнения, `and/or/not`, `#`), компиляция в простое дерево, исполнитель с лимитами D5.
- Стандартная библиотека: `ipairs, pairs, next, type, tostring, tonumber (целые), select, error, assert, pcall`; `table.insert/remove/sort/concat/unpack`; `string.len/sub/upper/lower/format (%d %s)/rep/find (простой)`; `math.min/max/abs/floor/clamp`. Всё детерминировано.
- Хост-функции регистрируются из Rust (типизированный мост к `Game`).
- Сообщения об ошибках с файлом и строкой.
- Тесты: синтаксис, семантика, лимиты, попытки побега из песочницы (`load`, `_G`, метатаблицы, `string.rep` на гигабайты, бесконечные циклы), сборка в wasm32.
- Документация `docs/packs/lua.md`.

### Фаза A2 — формат пакета и сборка пакета Classic
- `docs/packs/format.md`, JSON-схемы (для проверки) `docs/packs/schema/*.json`.
- `tools/pack.py build <src> -o <file>` и `tools/pack.py check <file>`; исходник пакета Classic собирается из нынешних данных: `data/cards.json` (имена и тексты на 8 языках), `data/card_layout`, `data/keywords.json`, `data/voice_lines.json`, арт (`art/cards`; `art/custom` — отдельный набор только локально), звуки и музыка (`audio/`), колоды (`game/decks.gd` → `decks/*.json`), ранги 2014 (из исследования), миссии обучения.
- Рядом — каталог эффектов `docs/packs/fx.md` (из нынешних эффектов `ui/table_fx.gd` и др.).

### Фаза A3 — сервер: один вход, S3, реестр пакетов, админка пакетов
- `kicked` при втором входе (D15) + тест.
- Слой хранилища (S3 и папка), `docker-compose.yml` + `server/Dockerfile`; выбор S3-хранилища (D10) — записать.
- Таблицы SeaORM: `packs` (id, version, rules_hash, content_hash, size, owner (null = админ), enabled, created), миграция.
- API игры: `packs {}` → список пакетов сервера и своих; скачивание `GET /packs/<content_hash>.cardpack` (по токену); загрузка своего пакета `POST /packs` (лимиты); удаление своего.
- Админка (Preact): страница «Игры»: загрузка, проверка, включение, удаление, кто сколько играет; события в журнал.
- Пока движок не умеет пакеты (фаза B) — проверка пакета ограничена разбором манифеста.

### Фаза A4 — пакет «Неон» (киберпанк): дизайн и ресурсы
- Документ дизайна: сеттинг, 3 чемпиона с силами (используют существующие механики, новые имена), ≤ 60 карт (классовые и нейтральные), свои имена механик, новые сочетания эффектов, статы с прикидкой баланса (кривая маны, ценность по стоимости).
- Арт через Codex (≈ 60 карт + 3 чемпиона + 3 силы + рубашка + фон/лого), свои звуки и музыка (генерация, как `tools/gen_audio.py`), тексты на 8 языках.
- Скрипты Lua карт — после A1 (API может уточниться в B).

### Фаза B — движок с пакетами
- Движок загружает пакет (правила, механики, карты, скрипты) → `Ruleset`; несколько наборов правил в одном `Engine`; `new` принимает пакет (`pack: rules_hash`), op `load_pack` (байты zip или распакованные файлы).
- Нейтральные механики внутри (D6), имена пакета в снимке и хэше (D7).
- Все хуки карт Classic переносятся из Rust (`rust/engine/src/cards/*.rs`) в Lua пакета Classic; Rust-хуки удаляются; миссии обучения — в пакет.
- **Проверка: все записанные партии (7833) совпадают с пакетом Classic на Lua без единого расхождения.** Плюс тесты API пакетов, лимиты Lua в партии (ошибка скрипта → понятный конец партии).
- Сборка в wasm и Android остаётся.

### Фаза C — клиент
- `PackManager`: встроенные и скачанные пакеты, индекс, кэш, удаление кэша, импорт файла (нативно — диалог, веб — выбор файла через JS).
- Экран «Игры»: список пакетов, выбор активного, наборы арта/звуков/музыки, удаление.
- Весь интерфейс берёт данные из пакета: карты, тексты, механики и подсказки, классы и цвета, чемпионы, арт, звуки, музыка, реплики, ранги и эмблемы, таймеры (фитиль), раскладка текста.
- Каталог эффектов (D16) по именам.
- P2P: согласование пакета в `hello`, предложение и передача (D13), проверка хэша, кэш.
- Сервер: список пакетов сервера, выбор пакета для очереди/арены/приглашения, скачивание и кэш, загрузка своего пакета.
- Несколько серверов (D14), обработка `kicked` (D15), красивое оформление новых экранов в стиле игры.

### Фаза D — сервер с пакетами
- Движок сервера грузит пакеты из хранилища по `rules_hash`; очереди, ранги и арена — по пакету; таймеры и ранги — из `rules.json`.
- Дружеские игры со своими пакетами игроков (D12).
- Полная проверка пакета при загрузке (D11); «Неон» по умолчанию (D11).

### Фаза E — «Неон», проверка, релиз, отчёт
- Скрипты карт «Неона»; баланс: тысячи партий бот против бота, доля побед каждого чемпиона в пределах 45–55 %, правка статов.
- Проверка вживую: веб и macOS; P2P (передача пакета), сервер (скачивание пакета, очередь «Неона», дружеская игра со своим пакетом), второй вход выкидывает первый, несколько серверов; админка «Игры».
- CI (пакеты собираются в релиз; `res://packs`), версия, журнал изменений на 8 языках, сайт.
- Итоговая интерактивная HTML-страница с тем, что сделано, как это работает и как пользоваться; открыть в браузере.

## 5. Риски

- Перенос ~530 карт в Lua — самая большая работа; паритет на 7833 партиях делает её проверяемой.
- Скорость Lua в браузере: замерить партию бот против бота; цель — не медленнее 3× нынешнего.
- Размер пакета Classic (арт ≈ 40 МБ) для передачи в P2P — показывать прогресс; передавать только то, что нужно для игры (правила + тексты), если у гостя нет арта? — нет, передаём весь пакет; арт можно пропустить флажком «только правила» (заглушки вместо арта).
- Хранилище S3 в Docker: если выбранный образ недоступен — запасной backend «папка».

## 6. Заметки по ходу работ

- A3: сервер пока считает `rules_hash` сам (SHA-256 по `path:sha256` файлов правил). В фазе D хэш считает движок по правилам `docs/packs/format.md` (как `tools/pack.py`), сервер переходит на него.
- A3: «люди, которых он приглашает» (D12) пока = друзья владельца пакета.
- B1 (движок с пакетами, первая часть): `Ruleset` из пакета (zip через miniz_oxide или папка; `rules_hash` совпадает с `tools/pack.py`, тест `tests/packs.rs`), кэш наборов правил по `rules_hash` на весь процесс (наборы правил не освобождаются: игры ссылаются на них; число ограничено числом разных пакетов), API `load_pack`, `packs`, поле `pack` в `new/hooks/validate/draft/data_hash`. Встроенный набор Classic собирается при сборке (`rust/engine/build.rs`: правила, миссии, скрипты из `packs/classic`, `cards.json` из `data/cards.json` + `cards.patch.json` без текстов; rules.wasm стал меньше: 1,10 МБ против 1,36 МБ).

- B1: Lua-интерпретатор игры не копируется для каждого хода, который пробует бот (копия кучи полного пакета ≈ 0,1 мс, бот пробует миллионы ходов): игра и её копии для просмотра вперёд берут один интерпретатор по очереди; `new {copy}` даёт отдельный.
