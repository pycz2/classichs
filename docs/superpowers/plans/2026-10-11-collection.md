# Коллекция и колоды — план реализации

**Spec:** `docs/superpowers/specs/2026-10-11-collection-design.md`
**Исполнение:** inline (Native), один финальный ревьюер. Владелец заранее утвердил план.

## Global Constraints

- Godot 4.7.2, GDScript; строки интерфейса через `tr()`.
- Логика без UI (`game/`) — тесты в `tests/`; UI — headless-тесты и снимки экрана.
- Хранение только через `user://` (в вебе — IndexedDB).
- `CHANGELOG.md` — запись на каждую задачу с поведением; в конце версия `0.3.0`.

## Review Focus

1. Импорт мусора, пустой строки, кода другого формата, кода с картами вне Classic: понятная ошибка, ничего не создаётся.
2. Битый или пустой `decks.json`: игра запускается, колоды не теряются молча (битый файл сохраняется рядом).
3. Добавление 3-й копии, 2-й легендарной, карты чужого класса, 31-й карты: отказ с подсказкой.
4. Имя колоды: пустое, очень длинное, с кавычками и Unicode — сохраняется и загружается без порчи.
5. Тренировка с неполной колодой (меньше 30 карт): запуск запрещён с понятным сообщением.

## Задачи

1. **Данные:** `legacyDbfId` в `extract_cards.py`; `CardDb.by_dbf` понимает оба id. Тест.
2. **`Deck`:** модель, лимиты, валидация. Тесты.
3. **`DeckCode`:** encode/decode, эталонный код HearthSim, legacy `dbfId`, текст клиента, ошибки. Тесты.
4. **`DeckStore`:** сохранение и загрузка, битый файл. Тесты.
5. **Коллекция (UI):** `ui/collection_view.gd` — страницы, вкладки классов, фильтр стоимости, поиск, режим сборки колоды. Тесты.
6. **Список колод (UI):** `ui/deck_list_view.gd` — новые/удаление/копия/переименование, импорт и экспорт кода. Пункт «Коллекция» в меню. Тесты.
7. **Тренировка:** выбор сохранённой колоды; запрет неполной колоды. Тесты.
8. **Web-проверка:** сохранение колоды переживает перезагрузку страницы; снимки экрана; `CHANGELOG`, версия `0.3.0`.
