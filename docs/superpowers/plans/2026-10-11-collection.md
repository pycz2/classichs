# Коллекция и колоды — план реализации

**Spec:** `docs/superpowers/specs/2026-10-11-collection-design.md`
**Исполнение:** inline (Native), один финальный ревьюер. Владелец заранее утвердил план.

## Global Constraints

- Godot 4.7.2, GDScript; строки интерфейса через `tr()`.
- Логика без UI (`game/`) — тесты в `tests/`; UI — headless-тесты и снимки экрана.
- Хранение только через `user://` (в вебе — IndexedDB).
- `CHANGELOG.md` — запись на каждую задачу с поведением; в конце версия `0.3.0`.

## Review Focus

1. Импорт мусора, пустой строки, кода другого формата, кода с картами вне Classic: понятная ошибка, ничего не создаётся.
2. Битый или пустой `decks.json`: игра запускается, колоды не теряются молча (битый файл сохраняется рядом).
3. Добавление 3-й копии, 2-й легендарной, карты чужого класса, 31-й карты: отказ с подсказкой.
4. Имя колоды: пустое, очень длинное, с кавычками и Unicode — сохраняется и загружается без порчи.
5. Тренировка с неполной колодой (меньше 30 карт): запуск запрещён с понятным сообщением.

## Задачи

1. **Данные:** `legacyDbfId` в `extract_cards.py`; `CardDb.by_dbf` понимает оба id. Тест.
2. **`Deck`:** модель, лимиты, валидация. Тесты.
3. **`DeckCode`:** encode/decode, эталонный код HearthSim, legacy `dbfId`, текст клиента, ошибки. Тесты.
4. **`DeckStore`:** сохранение и загрузка, битый файл. Тесты.
5. **Коллекция (UI):** `ui/collection_view.gd` — страницы, вкладки классов, фильтр стоимости, поиск, режим сборки колоды. Тесты.
6. **Список колод (UI):** `ui/deck_list_view.gd` — новые/удаление/копия/переименование, импорт и экспорт кода. Пункт «Коллекция» в меню. Тесты.
7. **Тренировка:** выбор сохранённой колоды; запрет неполной колоды. Тесты.
8. **Web-проверка:** сохранение колоды переживает перезагрузку страницы; снимки экрана; `CHANGELOG`, версия `0.3.0`.

## Журнал решений
- Эталонный код HearthSim оказался колодой охотника из карт Basic/Classic 2016 года: импорт через `legacyDbfId` прочитал её целиком; тест переделан на «импортируется», отказ проверяется отдельным кодом с неизвестной картой.
- UI коллекции, списка колод и тренировки написан раньше своих тестов (отступление от TDD, как в подпроекте 2); тесты добавлены сразу после.
- Карты в коллекции увеличены (×1,5, в конструкторе ×1,36); у длинных имён меньше шрифт; камень редкости перенесён на край арта.
- Web-проверка: колода создана, перезагрузка страницы, колода на месте (IndexedDB).
- Финальное ревью (Opus): «с исправлениями», 0 критических. Исправлено с тестом RED→GREEN: ошибка импорта видна внутри окна; карты, которых нет в данных, при загрузке отбрасываются, колода с неизвестным героем откладывается в копию; игрок узнаёт о повреждённом файле колод, старые копии не перезаписываются (`.bad1.json`, …); код с «образом» героя берёт класс по картам; обрезанный код — «это не код колоды»; код ищется во всех строках текста; имя колоды ограничено 60 символами везде, пустое имя заменяется именем по умолчанию; колода сохраняется после каждого изменения; тест не трогает настоящий файл колод.
- Решение по «образам» героев (спецификация говорила только о базовых героях): класс берётся по первой классовой карте колоды; без классовых карт — ошибка. Владелец заранее разрешил решать самому.
- Отложено (мелочи): увеличенная карта закрывает 4-й столбец коллекции; сообщения о правилах не называют карту; сообщение в списке колод не очищается; «A deck needs exactly 30 cards (now %d)» потребует форм множественного числа (подпроект 6); нет тестов на пустой файл и подсказки для 2-й легендарной и 31-й карты в UI.
