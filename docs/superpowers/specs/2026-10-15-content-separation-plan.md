# Отделение движка от контента и переименование игры

Дата: 2026-10-15
Статус: черновик для владельца (исследование, кода не меняли)

## 1. Цель

Сейчас в одном репозитории смешаны три вещи:

1. **Движок карточной игры.** Правила, очередь событий, ауры, lockstep и хэш состояния. Этот код наш собственный.
2. **Оболочка.** Экраны, бот, колоды, сеть, настройки, процедурная графика, звук. Тоже наш код, но в нём много зашитых имён из Hearthstone.
3. **Контент Blizzard.** Названия и тексты 534 карт, имена героев, сила героя, туториал с Хоггером и Иллиданом, фразы героев, оригинальный арт, а также сгенерированный арт, нарисованный по названиям карт Blizzard.

Задача: движок и оболочка не должны знать ни одного имени из Hearthstone. Весь контент переезжает в **пакет контента** (content pack). Пакет может подключить тот, у кого есть права, а любой желающий может собрать свой: своих чемпионов, карты, наборы и характеристики, либо поправить любую карту. Игра получает новое имя.

## 3. Решения

| Вопрос | Решение |
|---|---|
| Где граница | `engine/` и `game/` знают только id и правила из пакета. В коде нет ни одной строки из Hearthstone. Это проверяет тест: grep по коду ищет список запрещённых слов. |
| Формат карт | JSON. В Godot он встроенный, а TOML пришлось бы парсить самим. |
| Эффекты | Маленький декларативный язык эффектов в JSON и библиотека встроенных эффектов движка с нейтральными именами. Скриптов в пакетах, которые можно передать по сети, нет (раздел 6.4). |
| Слои пакета | `rules/` (влияет на игру и хэшируется) отдельно от `text/`, `art/`, `audio/` (оформление). Два игрока с одинаковыми правилами могут смотреть на разные названия и арт. |
| Хэш | SHA-256 сырых байтов файлов, без канонизации JSON. Сейчас `CardDb.data_hash()` устроен так же. |
| Контейнер | `.zip` с расширением `.cardpack`. В Godot 4.2+ есть `ZIPReader` и `ZIPPacker`. Для разработки подходит и папка. |
| Встроенный пакет | Свой нейтральный стартовый набор: свои чемпионы, карты, туториал и арт. Он идёт в публичной сборке. |
| Классика 2014 | Пакет `classic-2014` публично не распространяется. Владелец прав (или игрок для себя) собирает его инструментом из HearthstoneJSON, как сейчас `fetch_original_art.py`. |
| Сеть P2P | В `hello` передаются id, версия и rules-хэш пакета. Если пакеты разные, хозяин предлагает передать `rules/` и `text/` по каналу данных, гость соглашается. Арт не передаётся. |
| Сервер | Предпочтителен список разрешённых хэшей. Режим «хост присылает пакет» допустим только для пакетов без скриптов и с флагом `redistributable` (раздел 9). |

## 4. Таблица переименований

Столбцы: текущий id → id в движке → название для игрока в нейтральном пакете (en / ru). Пакет `classic-2014` вправе назвать механику по-старому: названия ключевых слов задаёт пакет, а движок знает только id. Так у владельцев прав всё будет выглядеть как раньше.

### 4.1. Основные понятия

| Сейчас | Движок | Игроку (en / ru) | Почему |
|---|---|---|---|
| Hero, `HERO`, `p.hero`, `g.hero()` | `CHAMPION`, `p.champion`, `g.champion()` | Champion / Чемпион | Просьба владельца. Слово «hero» общее, но вместе с «Hero Power» узнаётся сразу. |
| Hero Power, `HERO_POWER`, `hero_power` | `POWER`, `p.power` | Champion Power / Сила чемпиона | Короткий id, название для игрока по аналогии. |
| `hp_dmg()` | `power_dmg()` | — | |
| Minion, `MINION` | `MINION` (без изменений) | Minion / Существо | Слово общее. Переименование в коде (`g.minions`, 100+ мест) ничего не даёт. |
| Spell, Weapon, Durability, Armor | без изменений | Spell, Weapon, Durability, Armor / Заклинание, Оружие, Прочность, Броня | общие слова |
| Mana, Mana Crystal | `MANA` | Mana / Мана | общее слово (MTG и др.) |
| Fatigue | `FATIGUE` | Fatigue / Усталость | общее |
| Mulligan | `MULLIGAN` | Mulligan / Замена карт | общее |
| The Coin, `GAME_005` | `rules.second_player_card` | Spark / Искра (или Ember / Уголёк под название игры) | Монета из HS узнаётся сразу. Движок карту не знает: её id указывает пакет. |
| Arena | `draft` | Arena / Арена | общее слово; в коде режим называется draft |
| Tavern Brawl, Innkeeper | — | не используем | в коде их нет, и вводить не стоит |
| Emotes: Greetings, Well Played, Thanks, Wow, Oops, Threaten | без изменений | без изменений | общие фразы; озвучку и реплики задаёт пакет |
| Card back «Horde» | `banner` | Banner / Знамя | Horde — фракция Warcraft |

### 4.2. Ключевые слова и механики

| Сейчас (тег / mechanic) | Движок | Игроку (en / ru) | Решение |
|---|---|---|---|
| `TAUNT` Taunt | `GUARD` | Guard / Страж | Переименовать. Термин характерный для HS; «Guard» есть в TES Legends, слово общее. |
| `CHARGE` Charge | `HASTE` | Haste / Натиск | Переименовать. «Rush» не подходит: это другая механика HS. |
| `DIVINE_SHIELD` Divine Shield | `BARRIER` | Barrier / Барьер | Переименовать. Название из HS и WoW. |
| `WINDFURY` Windfury | `DOUBLE_ATTACK` | Flurry / Шквал | Переименовать. Windfury — термин Warcraft. |
| `STEALTH` Stealth | `STEALTH` | Stealth / Скрытность | Оставить: общее слово. |
| `BATTLECRY`, хук `battlecry` | `ON_PLAY`, хук `play` | Arrival / Появление | Переименовать: знаковый термин HS. Fanfare (Shadowverse) и Last Words тоже чужие, их не берём. |
| `DEATHRATTLE`, хук `deathrattle` | `ON_DEATH`, хук `death` | Farewell / Прощание | Переименовать: знаковый термин HS. |
| `ENRAGED` Enrage | `WOUNDED` (условие «пока ранен») | Bloodied / Ярость | Переименовать. В движке это не тег, а условие ауры (`_enrage` в `neutral.gd`). |
| `COMBO` Combo | `COMBO` | Combo / Комбо | Оставить: общее слово. В русском HS это «Серия приёмов», а мы пишем просто «Комбо». |
| `OVERLOAD` Overload, `overload_owed/locked` | `MANA_LOCK`, `lock_owed/locked` | Burnout / Выгорание | Переименовать. Overload — общее слово, но ключевое слово HS. «Выгорание» подходит к огненному названию. |
| `SECRET` Secret, зона `SECRET` | `TRAP`, зона `TRAP` | Trap / Ловушка | Переименовать: общее понятие, и в HS это не ключевое слово. |
| `CHOOSE_ONE` Choose One, `choose_one` | `CHOICE`, `options` | Choose One / Выберите | Фраза общая (MTG «Choose one —»). Меняется только id. |
| `SILENCE` Silence | `SILENCE` | Silence / Безмолвие | Оставить слово. В русском HS «Немота», у нас «Безмолвие». |
| `FREEZE` / `FROZEN` | без изменений | Freeze / Заморозка | общее |
| `SPELLPOWER`, `spellDamage` | `SPELL_POWER`, `spell_power` | Spell Power / Сила заклинаний | общее |
| `IMMUNE` | без изменений | Immune / Неуязвимость | общее |
| `ELUSIVE` | `SPELLPROOF` | Spellproof / Неуязвим к магии | Внутреннее имя HS, игроку не показывалось. |
| `CANT_ATTACK`, `AURA`, `ADJACENT_BUFF`, `TRIGGER_VISUAL`, `AFFECTED_BY_SPELL_POWER`, `ImmuneToSpellpower` | `CANT_ATTACK`, `AURA`, `ADJACENT`, `TRIGGER`, (выводится из эффекта), `NO_SPELL_POWER` | — | служебные |
| `DOUBLE_HEAL_DAMAGE` (Velen), `_velen()` | `POWER_MULTIPLIER`, `_multiplier()` | — | В движке не должно быть имени персонажа. |
| `HEAL_IS_DAMAGE` (Auchenai) | без изменений | — | общее |

### 4.3. Типы, редкости, классы, расы

| Сейчас | Движок | Нейтральный пакет | Решение |
|---|---|---|---|
| `rarity` FREE/COMMON/RARE/EPIC/LEGENDARY | `rarity`: 0–4. Названия даёт пакет. | Basic, Common, Rare, Epic, Legendary / Базовая, Обычная, Редкая, Эпическая, Легендарная | Слова общие (MTG и др.). Правило «легендарка 1 копия» переезжает в `rules.deck.max_copies_by_rarity`. |
| `elite` | `unique: true` | — | рамка-дракон рисуется по флагу |
| `cardClass` (9 классов + NEUTRAL) | строка класса из пакета; движок знает только `NEUTRAL` | свои классы, например Arcanist, Warden, Ranger, Zealot… | Каждое слово (Mage, Warrior…) общее, но набор из девяти с этими силами — узнаваемый отпечаток HS. В нейтральном пакете лучше свои классы. |
| Расы `BEAST, DEMON, DRAGON, MECHANICAL, PIRATE, TOTEM, UNDEAD` | строки из пакета (`tribes`) | Beast, Demon, Dragon, Construct, Pirate, Totem, Undead | общие слова; «Mech» → «Construct» по желанию |
| `MURLOC` | строка из пакета | Fishfolk / Рыболюд | Murloc — придуманное Blizzard слово, обязательно убрать. |
| `HERO_01…09` (Garrosh, Thrall, Valeera, Uther, Rexxar, Malfurion, Gul'dan, Jaina, Anduin) | id из пакета | свои чемпионы | только пакет |
| Силы героев (Armor Up!, Totemic Call, Dagger Mastery, Reinforce, Steady Shot, Shapeshift, Life Tap, Fireblast, Lesser Heal, INFERNO!) | id из пакета | свои силы | только пакет |
| `set`: VANILLA, MISSIONS, LEGACY… | `set` — строка пакета | `core`, `missions` | |
| Боссы туториала (Hogger, Millhouse, Cho, Mukla, Hemet, Illidan) | миссии пакета | свои боссы | только пакет |

### 4.4. События и хуки движка

Внутренние имена событий (`play`, `attack`, `turn_end`, `predamage`, `summon`, `death`…) уже нейтральные и не меняются. Хуки: `battlecry` → `play`, `deathrattle` → `death`, `hero_power` → `power`, `choose_one` → `options`, `on_choose` → `on_option`; `combo`, `combo_target`, `aura`, `cost_aura`, `can_play`, `on`, `now` остаются как есть.

## 5. Новое название игры: 10 вариантов

Намёк на «очаг + камень» (hearth + stone), но без самого слова Hearthstone. Проверка — простой веб-поиск 2026-10-15: точное название плюс «game/card game». Базы торговых марок (USPTO, EUIPO, WIPO), Steam, Google Play и App Store целиком не смотрел. **Перед выбором нужна отдельная проверка этих баз.**

| # | Название | Почему | Что нашёл поиск |
|---|---|---|---|
| 1 | **Inglestone** | *ingle* — огонь в очаге (шотл., устар.) + stone: прямая, но не очевидная аллюзия | ничего не найдено; уникально для поиска |
| 2 | **Emberstone** | угли очага + камень, звучит как имя игры | точного совпадения нет; рядом Etherstone (настольная, Asmodee) и много игр Ember-*: Emberkeep, Emberleaf, Emberwatch. Пространство тесное. |
| 3 | **Hobstone** | *hob* — полка у очага, где греют котелок + stone; коротко | игр нет; созвучно Gobstones (Гарри Поттер) — мелкий риск |
| 4 | **Cinderstone** | зола очага + камень | есть «The Agency of Anomalies: Cinderstone Orphanage» (2012, hidden object, Big Fish). Жанр другой, риск низкий. |
| 5 | **Kettlestone** | чайник над очагом, уют таверны | только деревня в Норфолке; игр нет |
| 6 | **Inglenook** | «уголок у камина», атмосфера таверны без слова stone | игр не найдено |
| 7 | **Mantelstone** | каминная полка + камень | не найдено |
| 8 | **Stokestone** | *stoke* — раздувать огонь; подходит к механике «Выгорание» | не найдено |
| 9 | **Tavernlight** | свет таверны, где играют в карты | есть Tavern Cards (Steam) и Tavern Rumble; «Tavern Brawl» — режим HS. Риск средний. |
| 10 | **OpenHearth** | открытый движок + очаг | игр не найдено, но слово *Hearth* ближе всего к торговой марке. Годится скорее как имя движка или репозитория, чем игры. |

Брать не стоит, всё занято: **Firestone** (известный трекер колод HS), **Stonehearth** (Radiant Entertainment, игроки там «Hearthlings»), **Hearthfire** (DLC Skyrim), **Fireside** (Blizzard Fireside Gatherings), **Heartbound / HearthBound** (Pirate Software и игра на itch.io), **Sabberstone / Metastone / Spellsource / Fireplace** (симуляторы HS).

Рекомендация: **Inglestone** (уникально и узнаваемо при объяснении) или **Emberstone** (звучнее, но тесно по поиску). К обоим подходит название стартовой карты второго игрока Ember / Уголёк.

## 6. Формат пакета контента

### 6.1. Структура

```
my-pack.cardpack (zip) или папка
├── manifest.json
├── rules/                  ← влияет на игру; входит в rules-хэш
│   ├── rules.json          ← числа и правила матча, колод и драфта
│   ├── classes.json        ← классы: чемпион, сила, цвета для процедурного арта
│   ├── cards.json          ← карты: характеристики и эффекты (DSL)
│   └── missions.json       ← миссии: колоды и правила боссов (если есть)
├── text/                   ← оформление; входит только в полный хэш
│   ├── en.json, ru.json…   ← названия, тексты, ключевые слова, классы, расы, миссии, реплики
│   └── layout/<lang>.json  ← необязательно: готовые переносы строк (иначе считаются при загрузке)
├── decks.json              ← готовые колоды (коды)
├── art/<card_id>.webp|png|jpg
├── audio/                  ← необязательно: ogg для реплик и музыки
├── tests/*.json            ← сцены-проверки карт (формат data/card_tests + ожидания)
└── LICENSE.txt
```

`manifest.json`:

```json
{
  "format": 1,
  "id": "org.example.starter",
  "version": "1.2.0",
  "engine": ">=1.0 <2.0",
  "name": {"en": "Starter Set", "ru": "Стартовый набор"},
  "authors": ["…"],
  "license": "CC-BY-4.0",
  "redistributable": true,
  "base": null,
  "default_locale": "en"
}
```

- `format` — версия формата пакета. Её понимает движок; несовместимая версия означает понятный отказ при загрузке.
- `version` — semver пакета, только для людей. Пакет однозначно определяет хэш (6.6).
- `engine` — диапазон версий движка.
- `redistributable` — автор разрешает передавать пакет другим игрокам. Без этого флага сеть и сервер не передают пакет, а только сравнивают хэши.
- `base` — для патч-пакетов (6.5): `{"id", "rules_hash"}` базового пакета.

### 6.2. `rules.json`

Всё, что сейчас лежит константами в коде:

```json
{
  "board": 7, "hand": 10, "max_mana": 10, "champion_health": 30,
  "start_cards": [3, 4], "second_player_card": "spark",
```

### 6.3. Карта

```json
{"id": "fireball", "type": "SPELL", "class": "arcanist", "rarity": 1, "cost": 4, "set": "core",
 "code_id": 315, "collectible": true,
 "target": "any",
 "play": [{"do": "damage", "to": "target", "n": {"spell": 6}}]}
```

```json
{"id": "raid_leader", "type": "MINION", "cost": 3, "attack": 2, "health": 2, "rarity": 0,
```

Поля: `id` (строка пакета; у `classic-2014` остаются `VAN_CS2_029`), `type`, `class`, `tribe`, `rarity`, `unique`, `cost`, `attack`, `health`, `durability`, `keywords`, `spell_power`, `mana_lock`, `collectible`, `set`, `code_id` (число для кодов колод: у классического пакета это dbfId или legacyDbfId, совместимость с кодами Hearthstone сохраняется), `look` (подсказки процедурному арту: `{"subject": "axe", "scene": "fire"}`, вместо поиска по английскому названию в `ui/art.gd`), плюс хуки эффектов.

### 6.4. Язык эффектов против скриптов

Сейчас 396 хуков — лямбды на GDScript. Статистика вызовов в `cards/*.gd`: `damage` 97, `spell_dmg` 68, `buff` 65, `draw` 42, `destroy` 30, `summon` 29, `heal` 22, `aura_add` 18, `random_*` 33, `add_to_hand` 11, `return_to_hand` 9, `freeze` 8, `transform` 7, `set_stats` 7, `take_control` 6, `silence` 6, `armor` 6, `equip` 5. Остальные примитивы встречаются 1–3 раза. Набор маленький и повторяющийся, поэтому на DSL ложится хорошо.

**Язык — JSON-дерево из трёх видов узлов.**

- **Действия** (`do`): `damage, heal, draw, summon, buff, set_stats, destroy, freeze, silence, transform, return_to_hand, take_control, give_keyword, armor, gain_mana, equip, add_to_hand, discard, copy, counter, cost_mod, replace_power, repeat, if, builtin`.
- **Выборки** (`to`, `from`): `target, self, my_champion, enemy_champion, my_minions, my_other_minions, enemy_minions, all_minions, all_chars, enemy_chars, adjacent, attacker, event_target`. Модификаторы: `{"random": sel, "count": n}` и фильтры `{"tribe": "BEAST"}`, `{"damaged": true}`, `{"has": "FROZEN"}`, `{"atk_le": 2}`.
- **Значения** (`n`): целое; `{"spell": 3}` — учесть силу заклинаний; `{"heal": 2}`, `{"power_dmg": 2}`, `{"count": sel}`, `{"stat": ["self", "attack"]}`, `{"sum": […]}`.

Хуки: `play`, `combo`, `death`, `power`, `options` (id вариантов для «Выберите»), `on: {event: {if, do}}`, `now` (до события: `predamage`), `aura`, `cost_aura`, `trap: {on, if, do}`, `can_play`, `target`.

Примеры классических карт:

```json
{"id": "VAN_CS2_031", "target": "any",
 "play": [{"do": "if", "cond": {"has": ["target", "FROZEN"]},
           "then": [{"do": "damage", "to": "target", "n": {"spell": 4}}],
           "else": [{"do": "freeze", "to": "target"}]}]}

{"id": "VAN_NEW1_012",
 "on": {"play": {"if": {"event": {"kind": "SPELL", "player": "me"}}, "do": [{"do": "buff", "to": "self", "atk": 1}]}}}

{"id": "VAN_EX1_287",
 "trap": {"on": "play", "if": {"event": {"kind": "SPELL", "player": "enemy"}}, "do": [{"do": "counter"}]}}

{"id": "VAN_EX1_295",
 "now": {"predamage": {"do": [{"do": "builtin", "name": "prevent_fatal_damage_once", "grant": "IMMUNE"}]}}}
```

**Встроенные эффекты (`builtin`).** Редкие и сложные эффекты (по прикидке 40–60 хуков: Ice Block, Jaraxxus, Faceless Manipulator, Mind Control Tech, Shadowform, Totemic Call, Lorewalker Cho, Brawl, Deathwing, отдельные ловушки) живут в движке на GDScript **под нейтральными именами**: `prevent_fatal_damage_once`, `become_champion`, `copy_minion`, `steal_random_if_more`, `upgrade_power`, `summon_missing_from`, `copy_spells_to_other_hand`, `destroy_all_but_one_random`. Пакет вызывает их по имени с параметрами (`{"do":"builtin","name":"summon_missing_from","cards":["…"]}`). Так у движка растёт библиотека общих эффектов, которую могут использовать и чужие пакеты, а в коде нет ни одного имени из HS.

**Почему не скрипты.**

- У GDScript нет песочницы: скрипт из пакета получает `FileAccess`, `OS`, `HTTPRequest`, `JavaScriptBridge` в вебе. Пакет со скриптами от соперника — это удалённое выполнение кода.
- `.pck`, `.tres`, `.res` и `.tscn` тоже могут нести скрипты. Загрузчик пакетов **никогда** не вызывает `ResourceLoader.load`/`load_resource_pack` для содержимого пакета: только `JSON.parse_string` и `Image.load_*_from_buffer`.
- Lua или WASM как встроенный язык — это новая зависимость, проблемы с веб-экспортом и ради 10% карт. Не нужно (YAGNI).
- Компромисс для разработчика: локальный **доверенный** пакет со скриптами только на десктопе. Его нельзя передать, его хэш не участвует в онлайне, а в меню видна плашка «скрипты». Добавлять, только если кто-то попросит.

**Прикидка покрытия:** примерно 85% хуков ложатся на DSL из ~25 действий; остальное закрывают встроенные эффекты. Точную цифру даст фаза 2 — по мере конвертации пакета `classic-2014` счётчик хуков на GDScript должен уйти в ноль. Проверка эквивалентности уже есть: тесты карт (`tests/test_cards_*.gd`) и сцены `data/card_tests`.

**Ограничения исполнения.** Существующий `MAX_QUEUE_STEPS = 5000`, а также глубина вложенности DSL ≤ 16, `repeat` ≤ 20, числа в `|n| ≤ 1000`. Любое нарушение отклоняет пакет при валидации, а не падает во время игры.

### 6.5. Подстройка карт и свои наборы

- **Свой пакет** — полный пакет со своими `rules/` и `text/`.
- **Патч-пакет** (`base` в манифесте) — переопределяет поля отдельных карт или правил базового пакета (`{"VAN_CS2_029": {"play": [… "n": {"spell": 7}]}}`) и может добавлять или убирать карты. Итоговый rules-хэш считается от базового и от патча (6.6). Онлайн обеим сторонам нужны оба пакета. Один уровень наследования, без цепочек.
- **Тексты карт с параметрами.** Чтобы правка «урон 6 → 7» не ломала текст, в тексте стоят ссылки на значения эффекта: `"Deal {play.0.n} damage."`. Подсветку от силы заклинаний `card_text.gd` уже умеет. Тексты без ссылок тоже разрешены — это ответственность автора.

### 6.6. Хэши

- **rules-хэш** = SHA-256 от строки `path:sha256(bytes)\n` по всем файлам `rules/`, отсортированным по пути. Для патч-пакета — SHA-256(база.rules_hash + патч.rules_hash). Только этот хэш нужен онлайну и серверу.
- **content-хэш** — то же по всем файлам пакета. Это идентификатор для кэша и передачи.
- Хэшируются сырые байты, без канонизации JSON. Это проще, и Godot `JSON.parse` превращает числа во float, что делает канонизацию ненадёжной. Цена: пересохранённый с другими отступами файл меняет хэш. Это приемлемо — для правок есть патч-пакеты.
- Версия движка по-прежнему сверяется в `hello`: код встроенных эффектов тоже влияет на игру.

### 6.7. Валидация

Один файл `game/pack_validator.gd` для игры и для инструмента (`godot --headless --script tools/validate_pack.gd pack.cardpack`). Проверяет:

1. Манифест: поля, `format`, диапазон `engine`.
2. Файлы: только разрешённые расширения (`.json .png .webp .jpg .jpeg .ogg .txt .md`). Пути без `..`, без абсолютных путей и без `\`. Лимиты размера (6.9).
3. Схему карт и DSL: известные поля, действия и выборки, ссылки на существующие id, отсутствие float, ограничения из 6.4.
4. Правила: соответствие тому, что поддерживает движок.
5. Тексты: только разрешённая разметка (`<b>`, `<i>`, ссылки на ключевые слова). Любой `[url]`, `[img]` и прочий BBCode экранируется. Тексты попадают в `RichTextLabel`, и без этого возможна инъекция ссылок и картинок.
6. Картинки: декодируются, размер ≤ 1024×1024.
7. Тесты пакета (`tests/*.json`) проходят. Это необязательно в игре, но обязательно для `tools/validate_pack.gd`.

JSON Schema не нужна: в Godot её нет, а ручной валидатор — один файл.

### 6.8. Локализация

`text/<lang>.json`:

```json
{
  "cards": {"fireball": {"name": "Огненный шар", "text": "Наносит {play.0.n} урона."}},
  "keywords": {"GUARD": {"name": "Страж", "text": "Враги должны атаковать существ со Стражем."}},
  "classes": {"arcanist": "Арканист"},
  "tribes": {"BEAST": "Зверь"},
  "champions": {"…": {"name": "…", "lines": {"greetings": "…", "attack": "…"}}},
  "missions": {"1": {"intro": "…", "lines": {"start": "…"}}},
  "events": {"BARRIER_LOST": "%s теряет барьер"}
}
```

- Порядок поиска: язык игрока → `default_locale` пакета → id.
- У движка есть свои нейтральные названия ключевых слов на 8 языках (из таблицы 4.2). Пакет их переопределяет, и у `classic-2014` снова будут «Провокация» и «Божественный щит».
- **Строки интерфейса с механиками.** В `data/i18n` фразы вроде «%s loses Divine Shield» не собираются подстановкой названия: в ru, de и pl падежи сломают предложение. Поэтому события, где фигурирует ключевое слово, — это целые фразы в `events` пакета, а у движка есть нейтральные фразы по умолчанию.
- Локали в стиле HS (`ruRU`, `enUS`) в `card_text.gd` заменяются на локали Godot (`ru`, `en`). Конвертер классического пакета их переводит.
- `card_layout`: переносы строк считаются при загрузке пакета и кэшируются в `user://packs/<hash>/layout/`. Пакет может принести готовые.

### 6.9. Арт и звук

- `art/<card_id>.(webp|png|jpg)`, рекомендовано 512 px. Загрузка через `Image.load_*_from_buffer` → `ImageTexture`. Чего нет — рисует процедурный арт по `look` и классу.
- Текущие «наборы арта» (`art/cards`, `art/original`, свои папки) становятся **арт-пакетами**: пакет с одним `art/` и манифестом `{"art_for": "<id пакета>"}`. Он не входит в rules-хэш и выбирается в настройках, как сейчас.
- Рамки, гемы, рубашки и эффекты стола остаются кодом движка: они наши.
- Аудио: `AudioStreamOggVorbis.load_from_buffer` (Godot 4.2+). По умолчанию звуки синтезированные.

Лимиты: `rules/` + `text/` ≤ 4 МиБ в распакованном виде; весь пакет ≤ 64 МиБ; одна картинка ≤ 2 МиБ; файлов ≤ 4000.

## 7. Загрузка пакета на платформах

| Платформа | Как попадает | Где хранится |
|---|---|---|
| Все | Встроенный нейтральный пакет в `res://packs/starter/` (папка в сборке) | res:// |
| Десктоп | Кнопка «Загрузить пакет» → `DisplayServer.file_dialog_show` (нативный диалог Windows, macOS, Linux/portal; иначе `FileDialog`). Перетаскивание файла в окно — сигнал `get_window().files_dropped`. По URL — `HTTPRequest`. | `user://packs/<content_hash>.cardpack` + `user://packs/index.json` |
| Android | Нативный выбор файла через `DisplayServer.file_dialog_show` (Storage Access Framework; *проверить версию Godot*: поддержка Android появилась в 4.3/4.4). Ссылка по URL. «Открыть с помощью» требует плагина — не делаем. | user:// (приватное хранилище приложения) |
| Веб | `<input type=file>` через `JavaScriptBridge`: файл читается в ArrayBuffer и передаётся в Godot колбэком. Перетаскивание на canvas: web-экспорт Godot 4 вызывает `files_dropped` (файл кладётся во временную папку; *проверить на 4.7.2*). URL через `HTTPRequest` при условии CORS (raw GitHub отдаёт `Access-Control-Allow-Origin: *`, вложения релизов — не всегда; *проверить*). Параметр страницы `?pack=<url>` для ссылок-приглашений. | user:// = IndexedDB. Вызвать `navigator.storage.persist()`, иначе браузер может вычистить данные. |

После загрузки: валидация → экран «Пакет X v1.2, автор, лицензия, 382 карты, rules-хэш abcd…» → «Подключить». Активный пакет хранится в `Settings`. Колоды в `user://decks.json` получают поле `pack` (rules-хэш или id). Существующие колоды при миграции получают `classic-2014`.

## 8. Онлайн P2P

### 8.1. Согласование

В `hello` (сейчас `data: CardDb.data_hash()`) добавляется:

```json
"pack": {"id": "org.example.starter", "version": "1.2.0", "rules": "<rules_hash>", "content": "<content_hash>",
         "size": 183402, "redistributable": true, "base": null}
```

- Источник истины — хозяин: играют его пакетом.
- Rules-хэши совпали — играем, даже если у сторон разные тексты и арт.
- Не совпали, но у гостя есть пакет с таким хэшем в `user://packs` — переключаемся молча (с уведомлением).
- Иначе:
  - если `redistributable: false`, отказ: «У соперника пакет X (v, хэш). Его нужно получить у автора»;
  - если `true`, гость видит «Соперник играет пакетом X v1.2 (180 КБ, автор, лицензия). Скачать? [Только на эту игру] [Сохранить] [Отмена]».
- Код приглашения (`net/signal_code.gd`) может нести id и хэш пакета, чтобы гость узнал о нём до соединения. Это необязательно.

### 8.2. Передача

- Передаются только `manifest.json`, `rules/`, `text/` (плюс `layout/`). Арт не передаётся: у гостя будет процедурный. Это убирает 95% объёма и большую часть юридических вопросов про арт.
- Сообщения по тому же надёжному упорядоченному каналу: `pack_offer {content_hash, files: [{path, size, sha256}]}` → `pack_accept`/`pack_decline` → `pack_chunk {i, n, data(base64)}` → `pack_done`.
- Куски по 16 КиБ сырых данных. Это безопасный размер сообщения WebRTC во всех браузерах; Chrome допускает 256 КиБ, но лучше не рисковать. Каждый файл сжимается `PackedByteArray.compress(GZIP)`. Гость распаковывает через `decompress(declared_size)`, где `declared_size` ≤ лимита. Зип-бомба невозможна: размер буфера задаём мы.
- У гостя: проверка sha256 каждого файла и итогового rules-хэша против `hello` → валидатор → игра.
- Лимит передачи 4 МиБ. Классический пакет без арта, если урезать до 8 локалей, по прикидке ~400 КБ JSON, ~100 КБ в gzip, то есть секунды.
- Арена: `arena_session.gd` делает то же в своём `hello`.

### 8.3. Безопасность

Пакет данных без скриптов, плюс все ограничения 6.4, 6.7, 6.9. Риски и защита:

| Угроза | Защита |
|---|---|
| Исполнение кода | Скриптов в пакетах нет. `ResourceLoader` на содержимое пакета не вызывается. |
| Зацикливание или раздутие эффектов | Лимиты DSL и `MAX_QUEUE_STEPS`. Валидация до игры. |
| Зип-бомба, огромные файлы | Передача пофайлово с объявленным размером; лимиты; при локальном импорте zip — проверка размера при чтении каждого файла. Если `ZIPReader` не даёт размер до распаковки, стоит лимит на сжатый размер пакета (*уязвимое место, проверить*). |
| Обход путей | Нормализация путей; запрет `..` и абсолютных путей. |
| Инъекция BBCode и ссылок | Белый список разметки (6.7). |
| Вредные картинки | Картинки не передаются. Локально — только декодеры Godot. |
| Оскорбительный контент | Пакет приходит только с согласия; «только на эту игру» не сохраняет его на диск. |

## 9. Сервер

Сейчас сервера нет, игра идёт lockstep между браузерами. Если сервер появится (рейтинг, скрытая информация, матчмейкинг), есть три варианта:

| Вариант | Плюсы | Минусы |
|---|---|---|
| **А. Сервер принимает только известные пакеты** (список разрешённых rules-хэшей, загружает оператор) | Оператор сам решает, на что у него есть права. Сервер не хранит чужой контент. Пакеты проверены заранее, проще античит и рейтинг (один пакет = одна таблица). | Новый пакет требует действий оператора. Свои пакеты онлайн только в P2P. |
| **Б. Хост присылает пакет, сервер ведёт матч** | Свои пакеты работают сразу. Пакеты хранить не нужно (кэш по хэшу на время матча). | Сервер исполняет чужие данные: допустимо только для DSL без скриптов, с лимитами и таймаутом матча. Оператор обрабатывает и, возможно, раздаёт второму игроку чужой контент, отсюда юридический риск. Нагрузку растит валидация. Рейтинг по произвольным пакетам бессмыслен. |
| **В. Гибрид** | Рейтинговые матчи — только А; дружеские комнаты — Б с флагом `redistributable` и согласием второго игрока. | Две ветки логики. |

Серверу нужны только `rules/` (тексты и арт — дело клиентов), поэтому объём малый в любом варианте. Сервер — тот же headless Godot с тем же движком. В режиме Б он может отдавать второму клиенту `rules/`, но не `text/`, если пакет не `redistributable`: тогда у второго клиента названия по id, а это плохой опыт. Рекомендация: **начать с А**, Б добавить, когда появятся пользовательские пакеты, которые нужны онлайн.

## 10. Читерство и целостность

- **Разные правила.** Rules-хэш в `hello` плюс хэш состояния после каждого действия, как сейчас: подменённая карта даёт рассинхрон на первом же применении.
- **Подменённый движок** со «своими» встроенными эффектами. Версия в `hello` проверяет только честного игрока; изменённый клиент даст рассинхрон хэша состояния. Lockstep это ловит, но не мешает знать колоду соперника.
- **Скрытая информация.** Lockstep требует, чтобы обе стороны знали обе колоды и сид. Пакеты этого не меняют. Решение — сервер (вариант А) или commit-reveal для колод. Это отдельная задача.
- **Сид выбирает хозяин.** Хозяин может перебирать сиды. Лечится общим сидом: каждая сторона присылает хэш своей половины, затем саму половину. Это стоит сделать вместе с изменением `hello`, задача маленькая.
- **Подделка «официального» пакета.** Имя и версия ничего не доказывают, доказывает хэш. Для известных пакетов в игре можно держать список «проверенных» хэшей. Подписи (ed25519) не нужны, пока нет каталога пакетов.
- **Арена.** Драфт использует RNG матча и rules-хэш, ничего нового.

## 11. Юридические заметки

*Это не юридическая консультация; перед публикацией нового имени и пакетов стоит спросить юриста.*

- **Авторское право** защищает выражение: названия и тексты карт, арт, реплики, музыку, логотипы, персонажей и лор. Правила и механики сами по себе им обычно не защищены: 17 U.S.C. §102(b), Baker v. Selden; DaVinci Editrice v. ZiKo Games (2016) — правила карточной игры не охраняются. Но копирование внешнего вида и «трейд-дресс» проигрывали: Tetris Holding v. Xio (2012), спор Spry Fox v. 6waves (2012). Отсюда вывод: нейтральный пакет должен отличаться не только названиями, но и выглядеть своим (рамки, арт, имена классов).
- **Подбор 382 карт с точными числами** — это фактические данные, но подбор и аранжировку можно пытаться защитить как компиляцию. Позиция неочевидна. Безопаснее не публиковать 1:1-клон под другими названиями как основной контент. Нейтральный пакет — собственный набор.
- **Торговые марки:** Hearthstone, Warcraft, Blizzard, а возможно и имена героев. Название игры не должно смешиваться с ними: «Classic HS» явно отсылает к HS, поэтому его меняем. Чем дальше от «Hearth-», тем лучше (см. раздел 5). Фразу «not affiliated with Blizzard» оставить в описании пакета `classic-2014`, а не в игре.
- **Сгенерированный арт** (`art/cards`) рисовали по названиям и текстам Blizzard: «Jaina», «Ragnaros», «Leeroy». Это производные изображения их персонажей, поэтому их место в `classic-2014`, а не в публичной сборке. То же касается `ui/art.gd` со словами-подсказками и, возможно, `ui/dragon_crest.png`, `menu_bg.jpg`, `board_bg.jpg` — проверить, по каким промптам они сделаны.
- **Данные HearthstoneJSON** извлечены из клиента игры. EULA Blizzard запрещает это пользователю клиента, но нам важнее, что публично распространять эти данные мы не должны. Инструмент, который *игрок сам* запускает у себя, — та же модель, что сейчас у `fetch_original_art.py`.
- **Передача пакетов по P2P** — это распространение тем, кто отправляет. Поэтому по умолчанию передаются только пакеты с `redistributable: true`, а в окне передачи у отправителя есть строка «вы подтверждаете право распространять этот пакет».
- **История git.** Даже после разделения `data/cards.json`, `art/cards`, `voice_lines.json` и старые сборки на gh-pages остаются в истории `pycz2/classichs`. Варианты: (1) новый репозиторий для нового имени с чистой историей; старый заархивировать или удалить; (2) переписать историю (ломает форки и ссылки). Рекомендую (1). Также убрать старые сборки из ветки gh-pages.
- **Лицензия пакета** — в манифесте и `LICENSE.txt`. Для нейтрального пакета: CC-BY-4.0 или CC0, чтобы его можно было свободно передавать.

## 12. План миграции

Каждая фаза заканчивается зелёным `./run_tests.sh` и рабочей игрой. Порядок такой, чтобы пакет `classic-2014` работал на каждом шаге.

### Фаза 0. Решения (без кода)
Выбрать имя, утвердить таблицу раздела 4, решить вопрос с репозиторием (11) и объём нейтрального пакета (фаза 5).

### Фаза 1. Слой пакета без изменения поведения
- `game/pack.gd`: загрузка пакета из папки. Текущие `data/*` перекладываются в `packs/classic-2014/`, а `CardDb`, `Cards`, `CardText`, `Decks`, `Missions`, `VoiceLines`, `CardLayout` читают из активного пакета.
- Константы из `engine/` (`HERO_POWERS`, `COIN`, `_blank` с `HERO_01`) переходят в `rules.json` и `classes.json`.
- `CardDb.data_hash()` → rules-хэш пакета.
- **Что ломается:** пути `res://data/...` в инструментах (`tools/card_layout.gd`, `site_cards.gd`, `screenshots.gd`, `check_card_tests.gd`) и в тестах. Решается механической заменой.
- **Риск:** низкий.

### Фаза 2. Переименование механик и понятий в движке
- Теги из 4.2, хуки из 4.4, `hero` → `champion`, `hero_power` → `power`, зона `SECRET` → `TRAP`, `_velen` → `_multiplier`.
- Пакет `classic-2014` при загрузке переводит старые `mechanics` (`TAUNT` → `GUARD`), поэтому его `cards.json` не трогаем до конвертации.
- **Что ломается:**
  - `tests/*.gd`: по меньшей мере 62 места с тегами и сотни с `hero` — правится sed'ом;
  - сохранённые сцены отладки (`tests/scenarios`, `data/debug_example.json`, `user://` позиции) — нужен перевод старых тегов при чтении `Scenario`;
  - `state_hash` и снимки — онлайн между старой и новой версией невозможен, но версия в `hello` и так отличается;
  - `ui/match_view.gd` (2395 строк) и `minion_view.gd` с отрисовкой эффектов по тегам.
- **Риск:** средний, изменение большое и механическое. Делать одним коммитом на понятие и гонять тесты после каждого.

### Фаза 3. Язык эффектов и конвертация классики
- DSL-интерпретатор в `engine/effects.gd` и встроенные эффекты в `engine/builtins.gd`. Карты переводятся с GDScript на JSON по классам; после каждого класса проходят его `test_cards_<class>.gd` и сцены `card_tests`.
- `cards/*.gd` уменьшается до нуля.
- **Что ломается:** `tests/test_coverage.gd` (проверяет, что у карт с текстом есть хуки) — переписать на «у карты есть эффект в DSL или она только с ключевыми словами».
- **Сложности:**
  - тонкий порядок событий: Knife Juggler, Ice Block, ловушки, смерть во время атаки;
  - карты со случайностью — DSL должен звать RNG в том же порядке, иначе изменятся сиды тестов и детерминированные симуляции (`tests/sim.gd`).
- **Риск:** высокий. Самая большая фаза (по прикидке 2–4 сессии). Хорошо, что тестов на каждую карту уже больше 640.

### Фаза 4. Отделение оформления
- Названия, тексты, ключевые слова, классы, расы, реплики, миссии, колоды, переносы и арт идут из пакета.
- `data/i18n/keys.json` чистится от имён: тексты туториала и подсказки (`tutorial.gd`, `tutorial_intro.gd` с Муклой, Хеметом, Иллиданом) переезжают в `missions` пакета; фразы истории с механиками — в `events`.
- `ui/art.gd`: таблица `KEYWORDS` оставляет только общие слова, имена персонажей удаляются, `HEROES` берётся из `classes.json` (`look`).
- Наборы арта превращаются в арт-пакеты.
- **Что ломается:**
  - **переводы**: 430 ключей × 8 языков, часть фраз переписывается целиком (падежи);
  - `test_i18n.gd`, `i18n_keys.gd`;
  - `test_card_fit.gd`: переносы теперь считаются при загрузке, проверка уходит в валидатор пакета;
  - `test_art.gd`: варианты процедурного арта считались по английским названиям, все картинки поменяются.
- **Риск:** средний; объёмная, но понятная работа.

### Фаза 5. Нейтральный стартовый пакет
- Свои 4–9 классов и чемпионов, 120–200 карт на тех же механиках, свой туториал из 3–6 миссий со своими боссами, сгенерированный арт по своим названиям, 8 языков.
- Это по сути геймдизайн, а не программирование: баланс, тексты, арт.
- **Сложности:** качество набора определит впечатление от игры без классики. Можно начать с минимального (2 класса по 30 карт + нейтралы), чтобы публичная сборка заработала, а потом расширять.
- **Риск:** высокий по времени, низкий технически.

### Фаза 6. Импорт пакетов и экран пакетов
- Валидатор, `.cardpack` (zip), загрузка из файла, URL и перетаскиванием, `user://packs`, выбор активного пакета, поле `pack` у колод, патч-пакеты.
- Инструмент `tools/build_classic_pack.py` (расширение `extract_cards.py`): собирает `classic-2014.cardpack` у игрока из HearthstoneJSON, плюс JSON-эффекты и миссии из репозитория.
- **Риск:** средний. Веб-специфика (JavaScriptBridge, CORS, persist) проверяется только в браузере. Есть путь проверки через `window.chs` и headless Chrome, как в онлайн-тестах.

### Фаза 7. Сеть
- `pack` в `hello` (обычная игра и арена), передача по каналу, общий сид (10), тесты на `LoopbackTransport` и `fake_rtc.gd`: несовпадение, согласие, отказ, порча куска, превышение лимита.
- **Риск:** низкий–средний.

### Фаза 8. Переименование и публикация
- `project.godot` `config/name`, `export_presets.cfg` (имена приложений), `ui/title_logo.gd`, иконки, заставка (`make_splash.gd`), README, CHANGELOG, лендинг `site/` и `site/i18n`, скриншоты `media/screens/*` (перегенерировать `tools/screenshots.gd` с нейтральным пакетом), `tools/site_cards.gd` и `site_data.py`.
- **Что ломается:**
  - **user://**: на десктопе путь данных зависит от `config/name`, и смена имени «потеряет» колоды и настройки. Решение: задать `application/config/use_custom_user_dir=true` и `custom_user_dir_name="Classic HS"` (старое имя), либо один раз перенести файлы при первом запуске. *Проверить `OS.get_user_data_dir()` в вебе*: IndexedDB привязана к origin, а `pycz2.github.io` один, так что при смене пути страницы данные, скорее всего, сохранятся, но путь внутри userfs может зависеть от имени.
  - **Android:** не менять `package/unique_name` (`io.github.pycz2.classichs`), иначе обновление станет новым приложением без данных. Имя ID пользователю не видно.
  - **PWA:** новый путь сайта = новое установленное приложение; старый адрес оставить с переадресацией.
  - **Коды колод** игроков продолжают работать с `classic-2014` (dbfId).
  - Ссылки на gh-pages, если меняется репозиторий.
- **Риск:** средний, организационный.

### Тест-гигиена после разделения
- `tests/engine/` — тесты движка на маленьком **тестовом пакете** `tests/fixture_pack/` (10–20 карт с говорящими id: `test_guard_2_3`). Не зависят ни от какого контента.
- Тесты карт (`test_cards_*`) уходят в `classic-2014` как тесты пакета и запускаются, только если пакет собран локально. В публичном CI их нет, потому что нет данных. Это главная потеря: **регрессии движка на классических картах в CI больше не ловятся.** Смягчение: в фикстурный пакет перенести по одной карте на каждый встроенный эффект и каждую сложную механику, с теми же ожиданиями.
- Тест-сторож: grep по `engine/`, `game/`, `ui/`, `net/`, `data/i18n` на список запрещённых слов (Hearthstone, Blizzard, Jaina, Murloc, Battlecry, Deathrattle, Divine Shield, Windfury, Hogger…).

## 13. Как сохранить нынешний опыт у тех, у кого есть контент

1. Игрок нажимает «Собрать классический пакет»:
   - на десктопе запускается `tools/build_classic_pack.py`;
   - в вебе, возможно, кнопка в игре скачивает `api.hearthstonejson.com` прямо из браузера (*проверить CORS и юридическую сторону: это всё ещё действие игрока, но инициирует его наша программа*).
2. Пакет `classic-2014` = наши JSON-эффекты, миссии и колоды (наша работа, публиковать можно) + названия, тексты, реплики и арт, которые игрок скачивает у себя.
   - Пакет восстанавливает старые названия механик («Провокация», «Божественный щит», «Боевой клич»), героев, Монету, туториал с Хоггером и 10 колод 2014 года.
   - Коды колод Hearthstone работают благодаря `code_id` = dbfId.
   - Сгенерированный арт `art/cards` и оригинальный арт — как арт-пакеты.
3. Старые колоды из `user://decks.json` при первом запуске получают `pack: classic-2014`. Если пакета нет, они видны серыми с подсказкой «нужен пакет classic-2014».
4. Онлайн: два игрока с собранным классическим пакетом получат одинаковый rules-хэш при одинаковой версии инструмента. Поэтому rules-часть стоит собирать из файлов репозитория, а не из HearthstoneJSON (числа у них могут поменяться в будущих выгрузках). Числа классики лучше заморозить в репозитории: это факты, а не текст. Названия же подтягиваются отдельно.
