# Подпроект 1: движок правил и данные карт

Дата: 2026-10-10
Статус: черновик на проверку

## 1. Контекст всего проекта

Цель: личная реконструкция Hearthstone в состоянии до Naxxramas. Игра работает в браузере (Godot, web-экспорт HTML5). Проект показывает, насколько точно можно повторить старую игру.

Требования ко всему проекту (из запроса владельца):

- Godot 4, 2D, web-экспорт.
- Все коллекционные карты Basic и Classic, все 9 классов, силы героев. Оригинальные названия и значения.
- Режимы: обучение (как в оригинале), тренировка против простого бота, P2P с другом.
- P2P через WebRTC и публичный STUN Google. Код подключения передаётся как текст.
- Коллекция без паков. Неограниченное количество колод. Колоды хранятся в браузере. Коды колод, совместимые с Hearthstone.
- Векторный схематичный арт. Простые анимации.
- Локализация, музыка, звуки, озвучка через TTS браузера на выбранном языке.
- 6 эмоций, кнопка «заглушить соперника», имя игрока.
- Во время матча можно открыть историю ходов с самого начала матча, без ограничения длины: кто что сделал, какие карты разыграны, взяты, сожжены, сколько урона от Fatigue и т.д.
- Полноэкранный режим, отключаемая тряска экрана, кнопка выхода.
- На экране показана версия игры. Клик по версии открывает журнал изменений нашей игры за всю историю, с прокруткой.
- Без сети работают бот и обучение.
- Не нужно: арена, ладдер, рейтинг, матчмейкинг.

Проект разбит на подпроекты. У каждого свой цикл «спецификация → план → реализация»:

1. **Движок правил и данные карт** — этот документ.
2. Игровой стол и тренировка с ботом.
3. Коллекция, колоды, коды колод.
4. P2P-мультиплеер.
5. Обучение.
6. Оформление: арт, звук, локализация UI, TTS, настройки, окно журнала изменений.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Версия правил и карт | Июнь 2014, последнее состояние перед Naxxramas. Это состояние формата Classic (2021). |
| Источник данных | HearthstoneJSON, набор `VANILLA` (382 коллекционные карты, включая наградные и промо) и карты обучения `TU4*`. |
| Сетевая модель | Lockstep с общим seed. По сети идут только действия игроков. |
| Описание эффектов | Код на каждую карту и библиотека примитивов (подход A). |
| Язык | GDScript. Web-экспорт C# в Godot 4 ненадёжен. |
| Версия Godot | 4.7.2 (установлена локально вместе с шаблонами экспорта). |
| Справочник по спорному поведению | Hearthstone Wiki, затем Fireplace и SabberStone. |

## 3. Объём подпроекта 1

Входит:

- Извлечение данных карт в `data/cards.json`.
- Движок: состояние матча, действия, проверка законности, порядок разрешения, ход, ауры, чары, секреты, Fatigue, конец игры.
- Хуки для всех 382 коллекционных карт, всех токенов и всех сил героев набора `VANILLA`.
- Детерминированный RNG и хэш состояния.
- Тесты и случайные симуляции в headless-режиме.
- Файл `CHANGELOG.md` и версия игры в `project.godot` (`application/config/version`). Журнал ведётся с первого коммита кода. Каждая задача, которая меняет поведение, добавляет запись. Формат: версия, дата, список изменений на русском языке.

Не входит:

- Любой UI, звук, арт.
- Бот (подпроект 2). Движок только даёт список законных действий, который бот потом использует.
- Карты обучения `TU4*`. Они попадают в `data/cards.json`, но их хуки делает подпроект 5.
- Сеть (подпроект 4). Движок только обеспечивает детерминизм.

## 4. Структура проекта

```
project.godot
CHANGELOG.md            ← журнал изменений, игра показывает его в подпроекте 6
data/
  cards.json            ← извлечённые данные, коммитятся в репозиторий
tools/
  extract_cards.py      ← скачивает HearthstoneJSON и делает data/cards.json
engine/
  game.gd               ← состояние матча, применение действий, порядок разрешения
  entity.gd             ← сущность с тегами и чарами
  card_db.gd            ← загрузка cards.json, поиск по id и dbfId
  actions.gd            ← типы действий, сериализация
cards/
  neutral.gd, druid.gd, hunter.gd, mage.gd, paladin.gd,

tests/
  run.gd                ← минимальный раннер
  test_*.gd
```

Все классы движка — `RefCounted`, не `Node`. Движок не зависит от дерева сцен и работает в headless-режиме.

## 5. Данные карт

`tools/extract_cards.py` скачивает `https://api.hearthstonejson.com/v1/latest/all/cards.json`. Скрипт оставляет карты с `set == "VANILLA"` и карты с `id`, который начинается на `TU4`. Для каждой карты он оставляет поля:

`id`, `dbfId`, `type`, `cardClass`, `rarity`, `cost`, `attack`, `health`, `durability`, `mechanics`, `referencedTags`, `collectible`, `name`, `text` (все 14 языков).

Результат — `data/cards.json`. Игра читает только этот файл и не ходит в сеть за картами.

Тексты и названия карт принадлежат Blizzard. Лицензия MIT в репозитории относится только к нашему коду.

## 6. Ядро движка

### 6.1 Сущности

`Entity` содержит:

- `id` — уникальный номер в матче.
- `card_id` — ссылка на карту в `cards.json`.
- `controller` — 0 или 1.
- `zone` — `DECK`, `HAND`, `PLAY`, `SECRET`, `GRAVEYARD`, `SETASIDE`.
- `play_order` — номер входа в зону `PLAY` или `SECRET`. По нему упорядочиваются триггеры и Deathrattle.
- `tags` — словарь базовых тегов: `ATK`, `HEALTH`, `DAMAGE`, `COST`, `TAUNT`, `CHARGE`, `DIVINE_SHIELD`, `STEALTH`, `WINDFURY`, `FROZEN`, `SILENCED`, `EXHAUSTED`, `ATTACKS_THIS_TURN`, `SPELLPOWER` и другие.
- `enchantments` — упорядоченный список чар.

Итоговые значения (`atk()`, `max_health()`, `cost()`, ключевые слова) считаются так:

1. Базовые теги из карты.
2. Чары по порядку применения. Чара может добавить значение (`+2/+2`) или установить его (`атака = 1`, Humility). Порядок важен.
3. Ауры, которые действуют сейчас.

`Silence` удаляет все чары, все хуки и ключевые слова сущности.

Если максимум здоровья уменьшается из-за того, что чара или аура исчезла, текущее здоровье становится равным `min(текущее, новый максимум)`. Урон сначала «съедает» бонус. Пример: 3/3 с чарой +2 здоровья (3/5) получает 2 урона и становится 3/3. После `Silence` это 3/3 без урона. Исчезновение бонуса здоровья никогда не убивает существо.

### 6.2 Игроки и зоны

У каждого игрока есть: герой, сила героя, слот оружия, рука (максимум 10), колода, стол (максимум 7 существ), секреты, кристаллы (максимум 10), `overload_owed`, `overload_locked`, счётчик Fatigue, счётчик карт, сыгранных в этот ход (для Combo).

### 6.3 Действия

Действие — словарь с полем `type`. Действия — единственный вход в движок и единственное, что идёт по сети.

| Действие | Поля |
|---|---|
| `mulligan` | `replace: [entity_id]` |
| `play` | `entity`, `target`, `pos`, `choice` (для Choose One) |
| `attack` | `attacker`, `defender` |
| `hero_power` | `target` |
| `choose` | `option` (выбор в середине разрешения, только Tracking) |
| `end_turn` | — |
| `concede` | — |

API движка:

- `Game.new(p0, p1, seed, first := -1)` — новый матч. `p = {"hero": id героя, "deck": [id карт]}`. `first == -1` — жребий через RNG матча.
- `game.legal_actions() -> Array` — все законные действия текущего игрока, включая все законные цели и позиции.
- `game.apply(action) -> Dictionary` — применяет действие и возвращает `{"ok": bool, "error": String, "events": Array}`. Незаконное действие возвращает `ok == false` и не меняет состояние.
- `game.state_hash() -> String` — хэш состояния.
- `game.to_dict()` — полное состояние для тестов и отладки.

UI и бот получают законные действия только из `legal_actions()`. Сами они правил не вычисляют.

### 6.4 Порядок разрешения

Каждое действие проходит одни и те же шаги:

1. **Шаг «до».** Триггеры на объявление: секреты и эффекты, которые реагируют до основного эффекта (Counterspell, Spellbender, Mirror Entity, Explosive Trap, Freezing Trap, Misdirection, Noble Sacrifice, Vaporize).
2. **Основной эффект.** Розыгрыш карты (Battlecry, заклинание, Combo, Choose One), бой или сила героя.
3. **Очередь триггеров.** Каждое событие проверяет триггеры всех сущностей в игре. Подходящие триггеры встают в очередь по `play_order`. Новые события добавляются в конец очереди.
4. **Фаза смертей.** Все существа и герои со здоровьем 0 или меньше умирают одновременно. Затем Deathrattle срабатывают по `play_order`.
5. **Пересчёт аур.**
6. Шаги 3–5 повторяются, пока очередь не опустеет.
7. **Проверка конца игры.** Если оба героя мертвы, это ничья.

Если действие ждёт выбора игрока (Tracking), движок останавливается в состоянии `AWAITING_CHOICE`. Единственное законное действие в этом состоянии — `choose`.

Точный порядок для спорных случаев (Knife Juggler и Deathrattle, Wild Pyromancer, Explosive Trap и смерть атакующего) движок берёт из Hearthstone Wiki для состояния на июнь 2014. Каждый такой случай получает отдельный тест.

### 6.5 Ход

Начало хода:

1. Игрок получает пустой кристалл (если меньше 10).
2. `overload_locked = overload_owed`, `overload_owed = 0`.
3. Все кристаллы, кроме заблокированных, восстанавливаются.
4. Существа и герой игрока теряют `EXHAUSTED`, счётчики атак обнуляются.
5. Триггеры начала хода.
6. Игрок берёт карту. Пустая колода даёт Fatigue. Полная рука сжигает карту.

Конец хода:

1. Триггеры конца хода.
2. Чары «до конца хода» исчезают.
3. Frozen тает по правилу Wiki на июнь 2014.

Начало матча: жребий, 3 карты первому игроку и 4 второму, mulligan у обоих, затем второй игрок получает The Coin.

### 6.6 События для UI

`apply()` возвращает упорядоченный список событий. Каждое событие — словарь с полем `type`. Типы: `draw`, `burn`, `fatigue`, `play`, `summon`, `attack`, `damage`, `heal`, `buff`, `silence`, `freeze`, `destroy`, `death`, `secret_played`, `secret_revealed`, `equip`, `transform`, `return_to_hand`, `mana`, `turn_start`, `turn_end`, `game_over`. UI проигрывает анимации по этим событиям.

### 6.7 История матча

`GameState.history` хранит всю историю матча без ограничения длины. Элемент — `{"turn", "player", "action", "events"}`. Первый элемент содержит начальные карты. Экран истории (подпроект 2) строит текст из событий и скрывает чужие взятые карты. История не входит в хэш состояния: она полностью выводится из действий.

## 7. API хуков карт

Каждый файл в `cards/` регистрирует хуки в общем словаре `id → хуки`. Карта без записи — «ванильная»: движок обрабатывает её ключевые слова из `mechanics` сам (Taunt, Charge, Divine Shield, Stealth, Windfury, Spell Damage).

Пример:

```gdscript
# cards/mage.gd
static func register(r: Dictionary) -> void:
	r["VAN_CS2_029"] = {  # Fireball
		"target": T.ANY,
		"spell": func(g, me, t): g.damage(me, t, g.spell_dmg(me, 6)),
	}
	r["VAN_EX1_559"] = {  # Archmage Antonidas
		"on": {"spell_played": func(g, me, ev):
			if ev.player == me.controller: g.add_to_hand(me.controller, "VAN_CS2_029")},
	}
```

Ключи хуков:

| Ключ | Назначение |
|---|---|
| `target` | Фильтр законных целей для розыгрыша. |
| `battlecry` | Эффект при розыгрыше существа. |
| `combo` | Эффект вместо обычного, если в этот ход уже сыграна карта. |
| `spell` | Эффект заклинания. |
| `choose_one` | Два варианта, каждый со своим `target` и эффектом. |
| `deathrattle` | Эффект при смерти. |
| `on` | Словарь `событие → обработчик`. Триггеры и секреты. |
| `aura` | Фильтр сущностей и эффект ауры. |
| `cost_mod` | Изменение стоимости (Sea Giant, Mountain Giant, Molten Giant, Summoning Portal). |
| `hero_power` | Эффект силы героя и её `target`. |
| `can_play` | Дополнительное условие розыгрыша (например, нужна цель). |

Примитивы `Game`, которые используют хуки: `damage`, `heal`, `destroy`, `summon`, `draw`, `add_to_hand`, `discard`, `buff`, `set_stats`, `silence`, `freeze`, `transform`, `return_to_hand`, `take_control`, `equip`, `gain_armor`, `gain_mana`, `spell_dmg`, `random_choice`, `targets(filter)`.

Хуки меняют состояние только через примитивы. Примитивы создают события и ставят триггеры в очередь.

## 8. Детерминизм

- Весь случайный выбор идёт через один `RandomNumberGenerator` с seed матча. Глобальные `randi()` и `randf()` в движке запрещены.
- Логика не использует числа с плавающей точкой.
- Порядок обхода всегда явный: по `play_order`, по позиции на столе или по `id`.
- `state_hash()` — SHA-256 от канонической сериализации состояния (`HashingContext`).
- Обе стороны в P2P запускают одну и ту же web-сборку, поэтому версия Godot и RNG одинаковые.

## 9. Тесты

- Раннер `tests/run.gd` находит функции `test_*` в файлах `tests/test_*.gd`, запускает их и показывает итог. Запуск: `godot --headless --script tests/run.gd`. Код выхода не 0, если есть ошибка.
- Помощник для тестов собирает нужную позицию за одну строку: руки, столы, мана, здоровье героев.
- **Тесты правил:** ход, мана, Overload, Fatigue, полная рука, лимит стола, Taunt, Stealth, Frozen, Windfury, Divine Shield, Silence, ауры, порядок триггеров и смертей.
- **Тесты карт:** у каждой карты с хуком есть минимум один тест сценария.
- **Тест данных:** все 382 коллекционные карты, все их токены и силы героев загружаются. У каждой карты с текстом эффекта (кроме ключевых слов) есть хук.
- **Случайные симуляции:** 1000 матчей со случайными законными действиями и случайными колодами. Ни одной ошибки движка.
- **Тест детерминизма:** матч, повторённый из того же seed и тех же действий, даёт тот же `state_hash()` после каждого действия.

## 10. Критерии готовности

1. `data/cards.json` создаётся скриптом и содержит все карты `VANILLA` и `TU4*`.
2. Все 382 коллекционные карты, их токены и все силы героев работают по правилам июня 2014.
3. Все тесты проходят в headless-режиме.
4. 1000 случайных матчей проходят без ошибок.
5. Повтор матча даёт одинаковые хэши.
6. Проект открывается и запускается в Godot 4.7.2. Web-экспорт пустой сцены с движком загружается в браузере. Это проверка, что движок не использует ничего, что недоступно в вебе.

## 11. Риски

- **Неоднозначные правила.** Wiki описывает текущие правила, а не правила 2014 года. Для спорных случаев используются история патчей на Wiki и поведение Fireplace. Каждое решение фиксируется тестом с комментарием.
- **Объём.** 382 карты — основной объём работы. Простые карты занимают 1–3 строки. Сложные карты (Brawl, Faceless Manipulator, Lord Jaraxxus, Mind Control Tech, Alarm-o-Bot, Illidan, Ragnaros) получают отдельные тесты.
- **Производительность GDScript в вебе.** Для пошаговой игры этого достаточно. Бот (подпроект 2) не делает глубокий перебор.
