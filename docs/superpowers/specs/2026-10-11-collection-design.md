# Подпроект 3: коллекция, колоды, коды колод

Дата: 2026-10-11
Статус: утверждено владельцем заранее («делать всё без лишних вопросов»)

## 1. Цель

Игрок смотрит все карты, собирает неограниченное количество колод, колоды сохраняются в браузере между запусками, их можно экспортировать и импортировать кодом, совместимым с Hearthstone. Тренировка (и позже сетевая игра) использует сохранённые колоды.

## 2. Объём

- **Коллекция:** все 382 коллекционные карты, страницы по 8 карт, вкладки классов (9 классов + нейтральные), фильтр по стоимости (0–6, 7+), поиск по имени (на языке интерфейса), увеличенная карта при наведении. Паков и пыли нет: все карты доступны.
- **Колоды:** список колод; новая колода (выбор героя); добавление карт кликом в коллекции, удаление кликом в списке колоды; лимиты: 30 карт, не больше 2 копий, легендарная — 1 копия, только карты класса героя и нейтральные; имя колоды; сохранение; удаление; копирование.
- **Хранение:** `user://decks.json` (в вебе — IndexedDB). Формат: `{"version": 1, "decks": [{"name", "hero", "cards": [id…]}]}`. Битый файл не роняет игру: колоды начинаются с пустого списка, битый файл сохраняется рядом как `decks.bad.json`.
- **Коды колод:** формат deckstring Hearthstone (base64 от varint: `0, 1, format, 1, hero, n1, singles…, n2, doubles…, 0`).
  - Экспорт: `format = 3` (Classic), `dbfId` карт набора `VANILLA`, герой — `dbfId` базового героя (`HERO_0x`). Списки отсортированы по возрастанию.
  - Импорт: принимает формат 1, 2, 3; карты по `dbfId` набора `VANILLA` и по `legacyDbfId` (оригинальные карты Classic/Basic), герой по `dbfId` базовых героев. Неизвестная карта или нарушение лимитов — понятная ошибка, колода не создаётся.
  - Также принимается текст, скопированный из клиента Hearthstone: строки `###` и `#` игнорируются, берётся строка с кодом.
- **Тренировка:** выбор колоды игрока (сохранённые колоды и базовая колода каждого класса); колода бота — базовая колода выбранного класса.

## 3. Компоненты

| Файл | Назначение |
|---|---|
| `tools/extract_cards.py` | Добавляет `legacyDbfId` для карт `VANILLA`. |
| `engine/card_db.gd` | `by_dbf` знает и `legacyDbfId`. |
| `game/deck.gd` | `Deck` (имя, герой, карты), `validate() -> String`, `can_add(id) -> String`, `card_class()`. |

| `ui/collection_view.gd` | Коллекция и сборка колоды. |
| `ui/deck_list_view.gd` | Список колод, импорт/экспорт. |
| `ui/training_setup.gd` | Выбор колоды. |

## 4. Тесты

- `DeckCode`: кодирование и декодирование колоды туда и обратно; разбор эталонного кода HearthSim (`AAECAR8GxwPJBLsFmQfZB/gIDI0B2AGoArUDhwSSBe0G6wfbCe0JgQr+DAA=` → герой 31, 6 одиночных, 12 двойных); код со старыми `dbfId` (оригинальные карты) импортируется в карты `VANILLA`; мусор — ошибка; текст клиента с `###`/`#` — разбирается.
- `Deck`: лимиты копий, легендарные, класс, размер 30.
- `DeckStore`: сохранение и загрузка; битый файл → пустой список и `decks.bad.json`.
- UI: коллекция строится, фильтры и страницы работают, клик добавляет карту в колоду, импорт кода создаёт колоду, тренировка стартует с сохранённой колодой.

## 5. Критерии готовности

1. Все тесты проходят.
2. Web-сборка: колода, собранная в коллекции, остаётся после перезагрузки страницы (проверка через headless Chrome с одним профилем).
3. Код колоды из игры импортируется обратно в такую же колоду.
