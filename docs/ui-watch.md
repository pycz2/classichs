# Наблюдение за интерфейсом (UI watch)

Режим отладки для правки экранов вдвоём. Владелец ходит по игре в обычном окне. Ведущий (ИИ в чате) читает, что
сейчас на экране, правит GDScript экрана, и окно показывает правку меньше чем за секунду, без перезапуска.

Код: `tools/ui_watch.gd` (узел, который `ui/main.gd` добавляет только в этом режиме), `tools/ui_watch.py` (команды
для ведущего), тесты `tests/test_ui_watch.gd`.

## Запуск

```sh
tools/ui_watch.py start            # игра в окне, свой профиль; печатает pid
tools/ui_watch.py start --real     # то же на настоящем профиле владельца
```

Внутри это `godot --path <repo> --log-file ~/ClassicHS-local/uiwatch/godot.log res://ui/main.tscn -- --ui-watch`.
С `--ui-watch` игра берёт свою папку данных `~/Library/Application Support/classichs-uiwatch` (на других
системах - папка `classichs-uiwatch` в папке данных ОС): настройки, колоды, входы на серверы и скачанные игры
владельца остаются нетронутыми. При первом запуске в этой папке игра спросит язык, как при первой установке.
Встроенные игры (Classic, Naxxramas, Neonfall) есть сразу, сервер добавляется в настройках.

## Команды ведущего

```sh
tools/ui_watch.py state            # экран, размер окна, язык, элементы с текстом, всплывающее, события, ошибки
tools/ui_watch.py state --all      # и элементы без текста
tools/ui_watch.py shot decks       # снимок окна; печатает путь к PNG
tools/ui_watch.py goto show_library
tools/ui_watch.py goto enter_game classic-2014
tools/ui_watch.py goto show_tournaments 12
tools/ui_watch.py size 1600 900
tools/ui_watch.py lang ru          # только на время сеанса, настройки не сохраняются
tools/ui_watch.py reload           # построить текущий экран заново
tools/ui_watch.py restart
tools/ui_watch.py stop
```

`goto` вызывает функцию `ui/main.gd` с этими аргументами, как это сделала бы кнопка. Аргумент, который читается
как JSON, передаётся числом, `true` или списком, остальное строкой. `enter_game` принимает id игры.

Папку можно сменить переменной `UI_WATCH_DIR` (её читают и игра, и `ui_watch.py`).

## Что лежит в ~/ClassicHS-local/uiwatch

- `state.json` пишется после любого изменения, не чаще раза в 0,3 с, через временный файл и переименование.
  В нём `seq` (только растёт, и после перезапуска тоже), текущий экран (класс, имя узла и вызов `main`, который
  его открыл, например `show_library` с аргументами), история экранов, размер окна, язык, профиль. Ещё там видимые
  элементы экрана: тип, имя, путь от экрана, прямоугольник в координатах 1280×720, текст до 80 символов,
  disabled, фокус, подсказка. Дальше идут открытые окна и всё, что видно поверх экрана (уведомления, панель
  друзей, турнирная панель), последние 50 событий и `error`, ошибка компиляции изменённого скрипта.
- Событиями считаются смена экрана, нажатие кнопки с её текстом, открытие и закрытие окон, появление
  всплывающего поверх экрана, ошибки и предупреждения из лога Godot (через `OS.add_logger`), команды,
  перезагрузки и перезапуски.
- `cmd.json` хранит одну команду. Игра проверяет его раз в 0,2 с, забирает и удаляет. Формат:
  `{"shot": "имя"}`, `{"goto": "show_library", "args": []}`, `{"size": [w, h]}`, `{"lang": "ru"}`,
  `{"reload": true}`, `{"restart": true}`.
- `pid`, `godot.log`, снимки `<имя>.png`.

## Правка без перезапуска

Раз в 0,3 с игра смотрит время изменения и размер файлов `ui/**/*.gd`, `game/**/*.gd`, `net/**/*.gd`,
`data/i18n/*.json`, шрифтов, `project.godot` и `tools/ui_watch.gd`.

- Скрипт из `ui/` (кроме `main.gd`) сначала компилируется отдельно. Если всё в порядке, игра перечитывает его
  с диска (`source_code` и `reload(true)`) и строит текущий экран заново тем же вызовом `main`, который его
  открыл. Окно, профиль и соединение с сервером остаются.
- Файл перевода перечитывается, экран строится заново.
- Всё остальное (`game/`, `net/`, `main.gd`, шрифты, `project.godot`, сам `tools/ui_watch.gd`) требует
  перезапуска. Игра запускает себя заново с теми же аргументами, размером и местом окна и с
  `--ui-watch-return <json>`, а сама закрывается. Новый процесс возвращает режим (без сервера или через сервер),
  игру, язык и экран.
- Если скрипт не компилируется, игра не падает. Старый экран остаётся, сверху появляется красная плашка с файлом,
  строкой и текстом ошибки, то же пишется в `error` в `state.json`. Плашка исчезает после исправления.

## Замеры

Замерено 26.11.2026 на Apple M1 Pro, окно 1280×720, экран «Мои колоды» (`show_collection`). Время считается от
записи файла до кадра, нарисованного после пересборки.

| Правка | От сохранения до кадра | Из них сама перезагрузка и сборка экрана |
|---|---|---|
| Надпись в `ui/deck_list_view.gd` (7 раз) | 186-448 мс, обычно около 330 | 74-167 мс |
| Строка в `data/i18n/ru.json` | 327 мс | 39 мс |
| Ошибка компиляции (плашка) | 96 мс | |
| Перезапуск после правки `game/app.gd` | 9,5-11,7 с | |

Остальное время горячей перезагрузки уходит на ожидание следующей проверки файлов (до 0,3 с). При перезапуске
почти всё время занимает запуск самого движка. `main._ready` начинается примерно через 8,9 с после старта
процесса, а на возврат к экрану после этого уходит около 0,3 с.

## Ограничения

- Время изменения файла известно с точностью до секунды. Две записи за одну секунду с одинаковым размером файла
  считаются одной (тогда поможет `tools/ui_watch.py reload`).
- Экран строится заново с нуля: прокрутка, выбранная вкладка и введённый текст сбрасываются. Конструктор колоды
  живёт внутри `DeckListView` и после пересборки возвращается к списку колод. То же с окнами внутри экрана
  (версии игры, жалобы, список изменений).
- Партия (`MatchView`), просмотр повтора и стол зрителя только сообщают своё имя. Их нельзя построить заново и
  нельзя вернуть после перезапуска: после перезапуска открывается меню игры.
- Скрипт перечитывается на месте. Константы, которые другие скрипты уже вставили в свой код, и статические
  переменные других классов не обновляются. Если экран после правки ведёт себя странно, поможет `restart`.
- Новый файл с `class_name` и новые картинки или шрифты требуют импорта (`godot --headless --path . --import`) и
  перезапуска.
- Текст, нарисованный в `_draw` (например, плитки колод), в `state.json` не попадает, его видно только на снимке.
- Снимок без окна (`--headless`) не делается, в событиях будет `shot_skipped`.
